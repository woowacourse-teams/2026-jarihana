# 채팅별 NOTIFY와 방별 1초 발행 비교

단일 인스턴스, 활성 방 256개, SSE 구독 1,024개, 분산 480 TPS로
25초간 12,000건을 저장했다. 커넥션 풀은 10개, SSE 틱은 1초, 보완
조회 간격은 5초다. 2회차에서 실행 순서를 뒤집었다.
각 셀은 채팅별 발행 → 방별 발행이다.

| 지표 | 1회차 | 2회차 |
| --- | ---: | ---: |
| 발행·수신 알림 | 12,000 → 6,249 | 12,000 → 6,241 |
| 발행 트랜잭션 | 12,000 → 25 | 12,000 → 25 |
| NOTIFY 큐 락 대기 기록 건수 | 5,052 → 0 | 4,708 → 0 |
| 기록된 큐 락 대기 합계 | 36,493 → 0ms | 35,209 → 0ms |
| 저장 커넥션 획득 p99 | 1,052.74 → 427.10ms | 900.74 → 634.62ms |
| 저장 p99 | 1,150.01 → 454.31ms | 955.29 → 786.12ms |
| SSE p99 | 1,858.45 → 2,156.85ms | 1,720.65 → 2,313.23ms |
| 저장 성공 응답 → SSE p99 | 1,321.55 → 1,818.51ms | 1,268.31 → 1,949.60ms |
| DB CPU | 62.64% → 47.18% | 60.71% → 45.96% |

큐 락 기록 문턱은 1ms다. 합계는 트랜잭션별 기록 시간을 더한 값이다.
모든 실행에서 저장 성공 12,000건, 기대 SSE 전달 48,000건, 누락·중복
0건을 확인했다. 배치 방식에서는 발행을 별도 트랜잭션으로 옮기고 변경
방을 한꺼번에 발행한다. 발행과 SSE 전송은 별도의 1초 틱이다.
