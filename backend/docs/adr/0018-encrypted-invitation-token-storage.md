# ADR 0018. 공유 초대 토큰의 해시와 암호문을 저장한다

- 상태: 채택. 발급·재시도의 링크 복원과 키 교체 검증 구현; 관리 상세 재복사는 후속 단계다.
- 날짜: 2026-10-11
- 결정 근거: 사용자는 같은 공유 링크를 나중에도 복사하기 원했고, 평문·해시 전용·암호문 저장의 차이와 키 관리 비용을 설명한 뒤 해시·암호문 저장을 채택했다.
- 관련 문서: [백엔드 ADR 목록](README.md), [초대 모델](../context/domain/model/invitation.md),
  [초대 API](../context/api/endpoints/invitations.md), [초대 운영](../operations/invitations.md).

## 배경

공유 링크의 토큰을 가진 가입 완료 회원은 초대를 수락할 수 있다. 토큰은 합류 자격을 증명하는 값이다.
해시만 저장하면 노출 범위를 줄일 수 있지만 발급 응답을 잃었을 때 같은 링크를 복원할 수 없다.
사용자가 요구한 재복사와 발급 재시도에 같은 링크를 반환하려면 복원 가능한 저장이 필요하다.

## 결정

1. LINK는 SecureRandom으로 생성한 32바이트 난수를 패딩 없는 Base64URL 43자로 표현한다. DIRECT에는 토큰을 만들지 않는다.
2. 조회에는 SHA-256 해시를 사용하고 재복사에는 AES-256-GCM 암호문을 사용한다. 원본 토큰은 DB에 저장하지 않는다.
3. 암호문에는 키 ID와 12바이트 난수 nonce·암호문·128비트 인증 태그를 담는다. 암호화 형식과 키 ID를 추가 인증 데이터로 검증한다.
4. 활성 키 ID와 키 목록은 서버 환경 설정으로 주입한다. 새 발급은 활성 키를, 기존 복원은 저장된 키 ID를 사용한다.
5. 복원한 토큰의 해시가 저장값과 일치하는지 확인한다. 키 누락·변조·복원 불일치는 INVITATION_UNAVAILABLE로 처리하고 원본·키·암호문을 오류 응답에 넣지 않는다.
6. 발급자+requestId의 동일 요청 재시도에는 기존 암호문을 복원해 같은 sharePath를 반환한다. 관리 상세의 재복사는 5단계에서 권한 검사와 연결한다.

## 검토한 대안

| 대안 | 장점 | 채택하지 않은 이유 또는 선택 이유 |
| --- | --- | --- |
| 해시만 저장 | DB에서 원본을 복원할 수 없다; 암호화 키가 필요 없다 | 같은 링크 재복사 요구를 충족하지 못한다 |
| 평문 저장 | 재복사가 간단하고 별도 키를 관리하지 않는다 | DB가 노출되면 유효한 공유 링크도 바로 사용할 수 있다 |
| 해시와 별도 키의 인증된 암호문 저장 (**채택**) | 재복사를 제공하고 DB 데이터만으로 토큰을 알 수 없게 한다 | 키 관리와 교체 비용을 감수한다 |

## 선택 이유

같은 링크를 다시 제공하는 요구를 유지하면서 DB 데이터 노출 시 원본 토큰의 노출을 줄인다.
조회용 해시와 복원용 암호문은 서로 다른 역할을 맡는다. DB와 암호화 키가 함께 노출되면 이 보호 효과는 사라진다.

## 감수하는 비용

- 별도 키 보관·백업·환경 주입이 필요하다. 키를 잃으면 해당 키로 발급한 링크를 다시 복사할 수 없다.
- 키 교체 시 이전 키를 같은 ID로 보관해야 기존 링크를 복원할 수 있다. 이미 발급한 링크는 새 키 활성화만으로 다시 암호화되지 않는다.
- 유효기간이 지난 링크라도 재조회가 가능하므로 이전 키 제거는 보존 정책과 함께 정해야 한다.
- 원본 토큰이 반환되는 API의 접근 권한·캐시·로그·분석 정제도 별도로 검증해야 한다.

## 후속 작업

- 5단계에서 권한 있는 관리 상세의 같은 링크 재복사를 연결한다.
- 7–10단계에서 프론트·로그·배포 환경의 원본 토큰 정제와 키 주입·복구 절차를 확인한다.
- 현재 검증은 로컬 임시 키·PostgreSQL·HTTP 기준이다. 공유·운영 키 등록이나 DB 적용은 수행하지 않았다.
