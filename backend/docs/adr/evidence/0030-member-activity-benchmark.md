# 백엔드 ADR 0030의 계정 활성 저장소 측정 근거

[백엔드 ADR 0030](../0030-account-activity-and-unlogged-chat-push.md)의 판단에 사용한 로컬 측정이다.

## 환경과 방법

- 실행일: 2026-11-06 KST. 기준 코드: `8712bcc0`의 `MemberActivityCommandRepository.updateIfNewer`. 실제 서비스 부하 검증은 아니다.
- PostgreSQL/pgbench 17.11, aarch64, 전용 Docker 컨테이너 2 CPU·1 GiB. 데이터는 일반 Docker 볼륨에 저장했고 tmpfs는 사용하지 않았다. 외부 네트워크·포트를 열지 않았다.
- 이미지 digest: `postgres@sha256:e38411452a464af89e5adadb8d223bf53b898d47d6ef918b2d58c08707350449`.
- fsync·synchronous_commit·full_page_writes·autovacuum은 on, checkpoint_timeout은 300초였다.
- 합성 회원 100,000행과 상태 100,000행. 회원은 id·withdrawn_at만 재현하고 상태 테이블의 PK·FK·타입과 UPSERT의 회원 조건·GREATEST·과거 시각 갱신 방지를 유지했다.
- 앱 Clock 대신 SQL statement_timestamp()를 사용했다. WebSocket, 서버 큐, JPA·연결 풀, 실제 채팅 저장, 푸시 워커는 포함하지 않았다.
- 매 회 상태 테이블 재생성·초기 데이터 삽입·VACUUM ANALYZE 후 3초 warmup, CHECKPOINT, 본 측정을 수행했다. LOGGED/UNLOGGED 순서를 번갈아 각 3회 실행했다. 홀수 반복이므로 완전 균형 배정은 아니다.
- 각 20초, 20,000건/초 조건은 각 30초로 총 36회다. pgbench prepared 프로토콜·2개 스레드, 100/1,000건/초는 연결 16개, 나머지는 32개다.
- 균등 분산 대상은 100건/초=1,000계정, 1,000건/초=10,000계정, 그 이상=100,000계정이다. 극단 경합은 1계정에 집중했다. 실제 기기별 정확한 10초 주기를 재현한 것은 아니다.
- 고정 부하는 Poisson 스케줄이며 `-L 5000`을 사용했다. 5초 이상 밀린 요청은 전송 전 건너뛴다. 로그상 지연에는 예정 시각부터 실행 시작까지의 대기도 포함된다.
- WAL은 측정 전후 pg_current_wal_insert_lsn() 차이다. 격리된 인스턴스 전체 값이며 테이블만의 WAL은 아니다. CPU는 DB·부하 생성기·로그·측정 명령 전체를 포함한다.

## 결과

표의 값은 조건별 3회 중앙값이다. p99 범위는 각 실행의 p99 최솟값~최댓값이며, 단일 요청의 범위가 아니다. [집계 CSV](0030-member-activity-benchmark.csv)에 소수점 원값과 추가 지표를 보관한다.

| 부하 | 방식 | 처리량(건/초) | p99(ms) | p99 범위(ms) | WAL(MiB) |
| --- | --- | ---: | ---: | ---: | ---: |
| 100건/초 | LOGGED | 99.0 | 11.02 | 9.78~44.17 | 0.551 |
| 100건/초 | UNLOGGED | 98.9 | 9.10 | 8.30~11.33 | 0.076 |
| 1,000건/초 | LOGGED | 992.2 | 123.21 | 32.84~236.48 | 5.426 |
| 1,000건/초 | UNLOGGED | 995.3 | 30.05 | 21.43~231.86 | 0.761 |
| 10,000건/초 | LOGGED | 9,989.4 | 802.62 | 42.18~2,275.02 | 54.547 |
| 10,000건/초 | UNLOGGED | 9,966.6 | 873.82 | 22.97~1,945.60 | 7.583 |
| 20,000건/초 | LOGGED | 16,763.2 | 4,798.28 | 4,280.67~4,835.18 | 125.120 |
| 20,000건/초 | UNLOGGED | 19,991.8 | 21.03 | 10.55~782.98 | 22.934 |
| 제한 없는 부하 | LOGGED | 16,847.0 | 54.33 | 54.07~54.65 | 86.623 |
| 제한 없는 부하 | UNLOGGED | 31,357.2 | 56.45 | 49.70~57.55 | 23.994 |
| 한 계정 1,000건/초 | LOGGED | 1,001.5 | 12.62 | 12.13~13.01 | 2.996 |
| 한 계정 1,000건/초 | UNLOGGED | 1,001.6 | 8.35 | 7.96~10.63 | 0.766 |

- 초당 1,000건의 동일 부하에서 WAL은 약 86% 감소했다. 제한 없는 부하의 처리량 중앙값은 약 1.86배였다. 서로 다른 처리량·측정 시간의 WAL 총량을 같은 부하의 절감률로 비교하지 않는다.
- 총 완료 보고 7,610,536건, 트랜잭션 실패 0건. 36회 모두 원본 로그 완료 수와 pgbench stdout 건수가 일치했다.
- 완료 요청 중 5초 초과와 전송 전 건너뜀은 각각 0건이다. 그러나 종료 시 남은 스케줄은 전부 skipped로 기록되지 않는다. 특히 LOGGED의 20,000건/초 조건은 목표 처리량에 못 미쳤으므로 누락·대기가 없었다고 해석하지 않는다.
- 이 5초 지표는 DB 부하의 지연을 보여 줄 뿐 실제 사용자의 15초 활성 만료 오판율이 아니다.
- 한 계정 경합에서는 처리 순서가 바뀐 이전 시각 보고를 갱신하지 않는다. 완료 보고 수와 실제 UPDATE 수는 다르므로 이 조건을 일반 분산 부하와 합치지 않는다.
- 실행마다 지연 편차가 크고 10,000건/초에서는 UNLOGGED의 p99 중앙값이 더 높았다. 모든 부하의 지연 개선이나 운영 처리 용량을 증명하지 않는다.

## 종료·복구 실험

같은 격리 DB의 LOGGED·UNLOGGED 테이블과 별도 영구 데이터 대조 테이블에 각 1행을 커밋한 뒤 정상 재시작과 SIGKILL 후 복구를 순서대로 확인했다.

| 상태 | LOGGED | UNLOGGED | 영구 데이터 대조 |
| --- | ---: | ---: | ---: |
| 종료 전 | 1행 | 1행 | 1행 |
| 정상 종료 후 재시작 | 1행 | 1행 | 1행 |
| 강제 종료 후 복구 | 1행 | 0행 | 1행 |

UNLOGGED의 상태 유실은 관찰했다. 이 때문에 실제 푸시가 어느 기기에 도착하는지까지 실행한 실험은 아니다. 해당 영향의 수용은 ADR에 기록한 작성자의 제품 판단이다.

## 한계와 자료 보관

20~30초의 DB 단독 측정으로 장시간 checkpoint/autovacuum, 운영 디스크·네트워크, 복수 백엔드, 장애 전환, 실물 기기 수신을 검증하지 않았다. 매 회 CHECKPOINT 뒤 측정하므로 초기 full-page image 비용도 포함한다. 부하 생성기와 DB는 같은 CPU 제한을 공유하며 트랜잭션 로그 기록 비용도 포함된다.

UNLOGGED의 dirty page가 측정 뒤 flush될 수 있어 구간 I/O 카운터로 총 디스크 쓰기 절감을 주장하지 않는다. WAL 감소와 총 디스크 I/O 감소는 구분한다.

저장소에는 판단에 필요한 방법·수치·집계 CSV를 보관한다. 실행 스크립트, 36회 stdout·트랜잭션 로그, 환경·결과 JSON은 작업 산출물 `member-activity-unlogged-benchmark/raw-evidence.tar.gz`에 별도로 보관했으며 이 저장소에는 넣지 않았다. 로컬 원본에 접근할 수 없는 독자는 CSV로 집계 수치를 확인할 수 있지만 원본 트랜잭션을 여기서 다시 집계할 수는 없다.

원본 식별용 SHA-256:

```text
summary.csv (원본 CRLF): 08190f07f0bea578e1da93a45c8462b4162dd27017d00692158ce303532d70a3
enriched-results.json: 485a28d2da1f9f795f11ca18cefd525f85cefff31423e0ad7f93816a60af3bb7
raw-evidence.tar.gz: e78150969bde8de08597e0ca46f5202706b44413a6fc97022647b4a1cb0f7053
```

저장소 CSV는 줄바꿈을 LF로 정규화했고 값은 원본과 동일하다. 이 비교 실험 자체는 개발 DB·PR 코드를 변경하지 않았으며 테스트 컨테이너와 볼륨은 종료 후 삭제했다. 이후 V23의 실제 적용·검증은 ADR의 구현 절에 별도로 기록한다.

측정 정의: [PostgreSQL 17 pgbench](https://www.postgresql.org/docs/17/pgbench.html). 저장소 특성: [CREATE TABLE의 TEMP·UNLOGGED 설명](https://www.postgresql.org/docs/17/sql-createtable.html).
