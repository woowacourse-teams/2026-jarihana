# 오목 관전

[오목 계약](gomoku.md), [게임방 채팅](gomoku-chat.md), [API 공통 계약](../common-contract.md)을 따른다.
가입 완료 회원만 공개 대국을 관전한다. 관전은 `gomoku_seat`을 생성하지 않으며 다른 방의 참가 좌석과 독립적이다.

## 입장과 퇴장

| Method | 경로 | 성공 |
| --- | --- | --- |
| POST | `/api/games/gomoku/rooms/{id}/observations` | 새 입장 201, 같은 요청 재시도 200 |
| DELETE | `/api/games/gomoku/rooms/{id}/observations/{participationId}` | 퇴장과 같은 퇴장 재시도 204 |

두 명령은 인증 쿠키와 CSRF 쿠키/헤더를 요구한다. POST 본문은 `{ "requestId": "UUID" }`다.
응답은 공통 봉투의 data에 `{ "participationId": "UUID", "chatStartSequence": "0" }`를 제공하며 `Cache-Control: no-store`다.

- `(room_id, member_id, request_id)`로 입장을 멱등 처리한다. `participationId`는 서버에서 발급한다.
- 새 입장은 공개/PLAYING/미만료이며 본인이 참가자가 아닌 방에서만 가능하다. 공개 여부는 403, 상태/참가 여부/종료된 요청 키 재사용은 409다. 방이 없으면 404, 본문/UUID 형식 오류는 400이다.
- 기존 입장 재시도는 FINISHED와 CLOSED에서도 같은 식별자를 반환한다. 결과와 재대결을 이어 보며, CLOSED는 마지막 판 표시를 위한 복구만 허용한다.
- 명시적 퇴장은 `left_at`을 기록하고 해당 입장의 모든 접속 lease를 삭제한다. 재입장은 새 requestId와 새 메시지 기준을 사용한다. 다른 탭의 입장은 종료하지 않는다.
- 식별자는 회원과 방에 귀속한다. 다른 회원의 식별자를 조회/퇴장/전송에 사용하면 403이다. 퇴장 후 같은 식별자로 상세/채팅/SSE에 접근하면 403이다.
- 입장과 메시지 저장은 같은 방 잠금으로 직렬화한다. 입장 당시 마지막 메시지 순번보다 큰 메시지만 조회할 수 있으며, 과거 커서로 이 제한을 우회할 수 없다.

## 상세와 SSE

기존 `GET /rooms/{id}`와 `GET /rooms/{id}/events`에 `?participationId=UUID`를 전달한다.
기존 참가자는 파라미터를 생략한다. 관전자는 유효한 본인 입장을 반드시 전달한다.
상세와 snapshot의 판 필드는 기존 계약을 유지한다. 관전자에게도 동일한 차례 기한과 결과를 전달한다.

- SSE는 기존 인증/토큰 만료/최대 120초 연결/재연결과 서버당 500개, 회원당 6개 제한을 공유한다.
- 방별 500ms 조회를 공유하며 채팅은 기존 `chat_changed`와 REST 복구를 사용한다. 채팅 비활성 설정에서도 관전은 가능하다.
- 퇴장한 관전의 기존 SSE는 다음 방 조회 주기에 닫힌다. CLOSED snapshot을 전달하면 스트림을 닫고 프론트엔드는 자동 재연결을 중단한다.
- 관전 입장, 접속 갱신과 관전자 메시지는 판 revision, 착수 기한과 방의 유휴 활동 시각을 변경하지 않는다.
- 준비/시작/착수/기권/초대/참가자 퇴장은 기존 참가자 권한을 유지한다. 관전 식별자로 권한을 얻을 수 없다.

## 관전자 수

게임방 SSE는 `spectators_changed` 이벤트로 현재 접속한 관전자 ID, 닉네임과 프로필 URL을 전달한다. 프로필 URL은 기존 참가자와 같은 GitHub 프로필 규칙을 사용한다.

```json
{"roomId": 7, "spectators": [{"memberId": 23, "name": "봄날", "avatarUrl": "https://avatars.githubusercontent.com/u/123"}]}
```

- 기존 방 SSE 권한이 있는 참가자와 관전자에게만 제공한다. 공개 대기실 응답에는 이름을 추가하지 않는다.
- 기존 방별 500ms 조회에서 한 번 조회해 연결들이 공유한다. 최초 조회와 명단 변경 시에만 보내며 판 revision이나 착수 기한을 변경하지 않는다. 명단 조회 실패는 게임 스트림을 끊지 않고 다음 주기에 재시도한다.
- 인원 집계와 같은 활성 lease/미퇴장/참가자 제외 조건을 사용한다. 회원 ID로 중복 제거하고 정렬하며 같은 인원수의 회원 교체도 전달한다. 종료된 방에는 추가 이벤트를 보내지 않는다.
- 클라이언트는 첫 수신과 이후 변경에서 현재 인원과 프로필 목록만 갱신한다. 별도 입장 문구는 표시하지 않는다. 이 이벤트는 현재 접속 상태이며 별도 입장 기록 재생은 제공하지 않는다.

`view=summary` 공개 목록 항목에 0 이상의 정수 `spectatorCount`를 추가한다. 목록의 상태/검색/정렬/커서 정책은 유지한다.

- 입장 이력은 `gomoku_observation`, SSE 연결은 `gomoku_observer_connection`에 저장한다. 여러 서버의 연결을 같은 DB에서 합산한다.
- 연결마다 별도 UUID와 45초 lease를 발급하고 유효한 연결은 15초마다 갱신한다. 정상 정리는 해당 연결만 삭제하므로 재연결된 새 연결을 지우지 않는다.
- 현재 시각보다 늦은 lease와 미퇴장 입장이 있는 회원을 방별로 중복 제거한다. 참가자와 CLOSED 방은 제외한다.
- 만료된 lease는 집계에서 즉시 제외하며 15초 주기로 물리 삭제한다. 관전 입장 이력은 퇴장 시각과 함께 보존한다.
- 한 페이지의 방 ID들을 일괄 집계한다. 대기실의 5초 갱신을 포함한 비정상 종료 표시 지연은 최대 약 50초다.

## 배포와 검증

V22는 신규 관전/접속 테이블과 기본값이 있는 `sender_role` 컬럼을 추가한다. 기존 V17~V21은 수정하지 않는다.
백엔드 전체가 관전을 지원하는 버전으로 전환된 뒤 새 프론트엔드를 배포한다. 롤백 시 관전 스키마와 입장 이력은 유지하며 구버전에서는 관전이 제공되지 않는다.
참가자 채팅의 `GOMOKU_CHAT_ENABLED` 정책은 유지한다. 채팅까지 사용하는 배포에서는 기존 운영 절차에 따라 활성화한다.

- `GomokuObservationAcceptanceTest`: 권한, 멱등 입장/퇴장, 메시지 경계와 역할, 재대결, 만료 lease와 중복 회원 집계.
- `GomokuServerCutoverTest.countsObserversAndRecoversChatAcrossTwoServers`: 실제 JVM 두 개에서 SSE/채팅/집계와 lease 갱신, 한 서버 강제 종료를 검증한다. 만료 경계는 SQL로 앞당겨 확인한다.
- 프론트엔드 관전 훅/Jest와 Playwright는 새로고침, 탭 복제, 명시적 퇴장 실패/재입장, 결과/재대결/종료, 읽기 전용 판과 반응형 화면을 검증한다. Playwright의 인증/API/SSE는 fixture이며 운영 OAuth와 프록시/부하 검증은 별도다.
