# 도메인 불변식

> 상태: 저장소 최신 설계 기준
>
> 구현·테스트·Swagger/OpenAPI와 충돌하면 임의로 해석하지 않고 차이를 보고한다.

이 문서는 구현 방법이 아니라 여러 모델 또는 여러 인스턴스 사이에서 항상 참이어야 하는 도메인 규칙을 정리한다.

> 이 절에는 “무엇이 항상 참이어야 하는가”만 적는다. 모델 하나의 필드 형식과 값 유효성은 `model/` 아래 상세 문서에서, 요청·이벤트에 따른 처리 흐름은 `business-policies.md`에서 다룬다. DB 제약, 락, 배치 같은 구현 수단은 별도 기술 구현 페이지에서 다룬다.

## Member

| 불변식                                                                                                    |
| --------------------------------------------------------------------------------------------------------- |
| `CREW` 회원은 같은 기수에서 `crewName`을 중복 사용할 수 없다.                                             |
| `COACH` 회원끼리는 `crewName`을 중복 사용할 수 없고, 코치명은 모든 `CREW` 회원의 크루명과 중복될 수 없다. |

## Member · Feedback

| 불변식 |
| --- |
| 피드백은 로그인한 회원만 작성할 수 있으며, `member_id`는 해당 작성 회원을 가리킨다. |

## Group

| 불변식                      |
| --------------------------- |
| 그룹 이름은 중복될 수 없다. 종료된 그룹의 이름 재사용 여부는 이 전역 유일성 정책에 따라 허용하지 않는 것으로 통합하되, 팀이 부분 유일성으로 바꾸려면 정책을 다시 결정해야 한다. |

## Group · GroupRecruitment

| 불변식                                     |
| ------------------------------------------ |
| `Group`과 `GroupRecruitment`는 1:N 관계다. |

## Member · GroupRecruitment · Registration

| 불변식                                                                                                                                             |
| -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 한 회원은 하나의 모집 공고에 하나의 신청만 가진다.                                                                                                 |
| 승인 또는 미승인된 신청이 있는 경우 같은 공고에 재신청할 수 없다. 또한 같은 그룹에 `PENDING` 신청이 존재하면 해당 그룹의 다른 공고에 신청할 수 없다. |
| 기존 신청이 `APPROVED` 또는 `REJECTED`로 결정된 뒤에는 다른 공고에 신청할 수 있다.                                                                 |

## Member · GroupMember

| 불변식                                               |
| ---------------------------------------------------- |
| 같은 회원의 같은 그룹 내 `GroupMember`는 하나뿐이다. |

## Group · GroupMember

| 불변식                                               |
| ---------------------------------------------------- |
| 활동 중인 그룹에는 `LEADER`가 정확히 한 명 존재한다. |

## Invitation · GroupMember · Registration

> 상태: 저장 모델·수락 이력 유일성·승인 출처 필드는 구현했다. 실제 초대 합류의 원자적 처리와 모집 정원 집계 변경은 후속 단계에서 구현한다.
> 모델 필드는 [초대 모델](model/invitation.md), 처리 흐름은 [초대 정책](business-policies.md#초대-발급과-합류)을 따른다.

| 불변식 |
| --- |
| 지정 초대의 대상은 한 회원이며, 다른 회원의 수락으로 바뀌지 않는다. |
| 같은 초대를 통해 같은 회원이 실제로 신규 합류한 수락 이력은 한 건이다. |
| 같은 그룹의 실제 소속은 초대·모집 승인 경로와 무관하게 그룹/회원당 하나다. |
| 초대 합류만으로 존재하지 않는 모집 공고나 신청 이력을 만들지 않는다. |
| 초대 합류로 승인된 신청은 일반 모집 정원 집계에 포함하지 않는다. 기존 일반 승인 이력은 계속 포함한다. |
| 초대 합류자는 실제 그룹 구성원 수에는 포함된다. |
| 초대 취소·만료·발급자 이탈로 이미 생성한 구성원 소속이 삭제되지 않는다. |
