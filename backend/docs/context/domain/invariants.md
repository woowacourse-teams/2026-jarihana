# 도메인 불변식

> 상태: Notion 설계 맥락 스냅샷
>
> 원본: [Notion 문서](https://app.notion.com/p/3ba0978a6e6c81f89deed43d644c762d)
>
> 동기화: 2026-08-15
>
> 구현·테스트·Swagger/OpenAPI와 충돌하면 임의로 해석하지 않고 차이를 보고한다.

이 문서는 구현 방법이 아니라 항상 참이어야 하는 도메인 규칙을 정리한다.

> 이 절에는 “무엇이 항상 참이어야 하는가”만 적는다. DB 제약, 락, 배치 같은 구현 수단은 별도 기술 구현 페이지에서 다룬다.

| # | 불변식 |
| --- | --- |
| 1 | 그룹 이름은 중복될 수 없다. |
| 2 | 기수가 있는 회원의 `crewName + generation` 조합은 중복될 수 없다. `COACH` 회원의 기수는 `null`이다. |
| 3 | `crewName`은 완성형 한글 2–4자만 허용하며 공백과 특수문자는 허용하지 않는다. |
| 4 | 일반 회원의 기수는 양수이며 가입 후 직접 수정할 수 없다. `COACH` 회원은 기수를 갖지 않는다. |
| 5 | 그룹 전체 정원에는 인원 제한이 없다. |
| 6 | 각 모집 공고에는 모집할 인원을 제한하는 1 이상의 `capacity`가 반드시 존재한다. |
| 7 | `Group`과 `GroupRecruitment`는 1:N 관계다. |
| 8 | 새 모집 공고가 생성되면 같은 그룹의 기존 활성 공고를 마감하고, 해당 공고의 `PENDING` 신청을 `SYSTEM` 주체로 즉시 `REJECTED` 처리한다. 가장 최신 공고만 마감되지 않은 상태일 수 있다. |
| 9 | `AUTO` 모집은 `capacity`를 초과해 신청·가입할 수 없으며, 신청 가능한 경우 즉시 자동 승인한다. |
| 10 | 승인제 모집은 `capacity`보다 많은 신청을 받을 수 있지만 승인 인원은 `capacity`를 초과할 수 없다. |
| 11 | 한 회원은 하나의 모집 공고에 하나의 신청만 가진다. 또한 같은 그룹에 `PENDING` 신청이 존재하면 해당 그룹의 다른 공고에 신청할 수 없다. 기존 신청이 `APPROVED` 또는 `REJECTED`로 결정된 뒤에는 다른 공고에 신청할 수 있다. |
| 12 | 같은 회원의 같은 그룹 내 `GroupMember`는 하나뿐이다. |
| 13 | 활동 중인 그룹에는 `LEADER`가 정확히 한 명 존재한다. |
| 14 | 모집 기간은 `startsAt <= endsAt`을 만족한다. `endsAt`이 없으면 상시 모집이다. |
| 15 | 신청 상태 전이는 `PENDING`에서 `APPROVED` 또는 `REJECTED`로만 일어난다. |
| 16 | `CLUB`, `STUDY`는 `RecurringGroupSchedule`만 가질 수 있고 `SessionGroupSchedule`은 가질 수 없다. 반복 일정이 없으면 유동적 일정이다. |
| 17 | `SESSION`은 정확히 하나의 `SessionGroupSchedule`을 가져야 하고 `RecurringGroupSchedule`은 가질 수 없다. 두 일정 클래스 사이에는 상속 관계가 없다. |
| 18 | 그룹 삭제와 그룹 종료는 서로 다른 도메인 명령이며, 삭제 요청이 종료 요청으로 자동 전환되거나 그 반대로 전환되지 않는다. |
| 19 | 생성 후 24시간 이내의 `ACTIVE` 그룹은 삭제만 가능하며 종료할 수 없다. |
| 20 | 생성 후 24시간이 지난 `ACTIVE` 그룹은 삭제할 수 없으며 종료만 가능하다. |
| 21 | 그룹 삭제는 그룹과 연관 데이터를 Hard Delete하며 `Group.status`를 변경하지 않는다. |
| 22 | 그룹 종료는 `Group.status`를 `ACTIVE`에서 `ENDED`로 변경하며 그룹과 연관 이력을 보존한다. |
| 23 | 그룹을 `ENDED`로 전환하면 마감되지 않은 모집 공고를 마감하고 해당 공고의 `PENDING` 신청을 `SYSTEM` 주체로 모두 거절한다. |
| 24 | 새 공고 생성 또는 승인 인원의 `capacity` 도달로 공고가 마감되면 기존 `PENDING` 신청을 `SYSTEM` 주체로 즉시 `REJECTED` 처리한다. 정원 미달 상태에서 공고 기간이 만료되거나 운영자가 수동 조기 마감한 경우에는 즉시 거절하지 않고, 마감 후 2주 동안 처리되지 않은 신청만 `SYSTEM` 주체로 자동 거절한다. 그룹 종료는 즉시 거절한다. |
| 25 | 승인 인원이 `capacity`에 도달하면 해당 모집 공고는 자동 마감한다. |
| 26 | `PENDING` 신청 철회는 상태 변경이 아니라 신청의 Hard Delete다. 이미 승인 또는 거절된 신청은 철회할 수 없다. |
