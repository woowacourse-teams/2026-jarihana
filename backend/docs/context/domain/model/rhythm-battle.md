# 행성이의 리듬 작살 1:1 대전

게임은 모임 소속과 독립적이며 가입 완료 회원 두 명이 같은 채보를 동시에 친다.
판정은 [공식 도전](rhythm-harpoon.md)과 같은 서버 엔진(`RhythmEngine`)으로 다시 계산하며, 공식 도전 랭킹과는 따로 집계한다.

## 방

- `RhythmBattleRoom`은 방장, 손님, 공개 여부(공개/초대 전용), 난이도를 가진다. 난이도는 방장이 만들 때 정하고 이후 고정한다.
- 회원은 `RhythmBattleSeat`(회원 ID가 기본 키)로 대기, 진행, 결과 상태의 방 하나에만 앉는다.
- 방은 `WAITING -> PLAYING -> FINISHED -> PLAYING`으로 진행하며 닫힌 방(`CLOSED`)은 재개하지 않는다.
- 두 사람이 준비한 뒤 방장이 시작한다. 준비할 때 각자 세균 이동 배속(1.0~3.0, 0.25 단위)을 고르며, 배속은 보이는 속도만 바꾼다.
- 시작하면 서버가 시드를 정하고 공통 시작 시각을 시작 요청 5초 뒤로 정한다. 두 사람은 같은 시드, 같은 난이도의 판을 친다.
- 대기 중 손님이 나가면 준비를 초기화하고 빈자리를 다시 모집한다. 방장이 나가거나 결과 상태에서 누군가 나가면 방을 닫는다.
  진행 중 나가기는 먼저 기권으로 판을 끝내고 결과를 남긴 뒤 처리한다.
- 대기와 결과 상태의 마지막 실제 활동 후 30분이면 닫는다. 조회와 재연결만으로 수명을 늘리지 않는다.
- 방을 닫으면 좌석을 풀고 채팅 본문을 지운다.

## 판과 승패

- `RhythmBattleRun`은 한 판에서 한 사람의 진행이다. `(room_id, game_number, member_id)`로 하나만 만든다.
  입력 묶음(`RhythmBattleBatch`)을 순번대로 저장하고, 마지막 묶음까지 다시 계산한 점수, 라이프, 판정별 수를 가진다.
- 묶음의 진행 시각은 공통 시작 시각부터 지난 서버 시간과 비교한다. 3초 넘게 앞서면 `CLOCK_AHEAD`, 15초 넘게 늦으면 `LAGGED`,
  30초 동안 묶음이 없으면 `STALE`로 기권 처리한다. 화면 이탈과 Esc는 `ABANDONED` 기권이다.
- 라이프를 모두 잃으면 `ELIMINATED`로 탈락하며 탈락 시각(`outAt`)은 마지막으로 놓친 세균의 판정과 공격 연출이 끝난 곡 시각이다.
- `BattleReferee`는 두 사람의 진행으로 승패를 정한다.
  1. 한 사람이 기권하면 상대가 이긴다(`FORFEIT`). 두 사람이 모두 기권하면 무승부다.
  2. 두 사람이 모두 탈락하면 더 늦게 탈락한 사람이 이긴다. 탈락 시각이 같으면 무승부다(`DRAW`).
  3. 한 사람만 탈락하면, 살아 있는 사람의 진행 시각이 그 탈락 시각에 닿았을 때 살아 있는 사람이 이긴다(`ELIMINATED`).
     그 전까지는 판정을 미룬다. 묶음이 늦게 도착해도 곡 시각으로 비교하므로 네트워크 지연이 승패를 바꾸지 않는다.
- 판정은 방 잠금 안에서 묶음, 기권, 만료를 처리할 때마다 다시 한다. 승패가 정해지면 방은 `FINISHED`가 되고 두 사람의 준비를 초기화한다.

## 대전 기록과 랭킹

- `RhythmBattleGame`은 시작한 한 판을 소유한다. `(room_id, game_number)`로 하나만 만들고, 시작 시 두 참가자와 난이도를,
  끝날 때 승자와 끝난 이유, 끝난 시각을 확정한다. 재대결이나 방 종료로 이전 결과를 수정하지 않는다.
- 랭킹은 끝난 판이 있는 비탈퇴 회원을 대상으로 승수 내림차순, 총 판수 오름차순, 회원 ID 오름차순의 순번이다.
  랭킹은 승/패/무 집계만 공개하며 다른 회원의 개별 대전 목록은 제공하지 않는다.

## 방 채팅

좌석의 `chatAfterId`가 대화 조회 하한이다. 들어오기 전의 대화는 보이지 않는다. 메시지는 회원별 `clientMessageId`로 중복 전송을 막는다.
채팅은 방의 마지막 활동 시각만 갱신하고 판 `revision`은 그대로 둔다.

## 실시간 연결

참가자는 SSE로 방 모습, 지금 판의 입력 묶음, 채팅을 받는다. 상대 판은 상대의 입력 묶음을 같은 시드의 엔진에 넣어 화면이 다시 그린다.
서버는 방마다 마지막 모습과 묶음, 채팅을 한 번만 읽어 두 연결에 나눠 보낸다.

API: [1:1 대전 계약](../../api/endpoints/rhythm-battle.md).
