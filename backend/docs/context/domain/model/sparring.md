# Sparring

회원 누구나 주제를 열고, 다른 회원은 원하는 때 참여한다. 1:1 방/매칭은 없다.

- `SparringTopic`: 주제, 민트/코랄 주장, 설명, 개설자, revision, 마감 일시 closesAt (기존 데이터는 없을 수 있음)
- `SparringVote`: 주제·회원당 하나. MINT/CORAL을 바꾸면 기존 표를 옮긴다
- `SparringPost`: 여러 번 남길 수 있는 영구 의견. 작성 당시 진영과 작성자를 보존한다
- `SparringPost.replyTo`: 같은 주제의 원문 참조. 받아치기도 같은 의견 모델이다

표수는 Vote만 센다. 의견 수나 리플레이/시각 효과는 표수에 영향을 주지 않는다.
주제 행 잠금으로 투표·의견 저장·revision 증가를 직렬화한다.
같은 전송 번호의 동시 재시도는 주제/회원/requestId 유일 제약과 잠금으로 한 글이 된다.
SSE는 커밋된 revision만 관찰한다. 영구 데이터의 원본은 PostgreSQL이며 브라우저 저장소는 사용하지 않는다.

대표사진은 선택이며 이미지 참조의 `SPARRING_REPRESENTATIVE` 유형으로 주제에 하나만 연결한다.
사진은 생성자의 만료 전 임시 업로드에서 `sparrings/{topicId}/{파일명}`으로 이동한다. 이미지 소유권의
`attachedSparringId`와 참조의 null `groupId`로 그룹 이미지와 분리하므로 숫자 ID가 같은 그룹의 삭제가
토론 사진에 영향을 주지 않는다. 마감 후에도 참조와 공개 조회를 유지한다. 토론 생성·이미지 참조는
같은 트랜잭션이며, 롤백으로 남은 스토리지 복사본은 기존 이미지 이동 의도/복구 작업으로 회수한다.

마감은 현재 시각보다 이후로 지정하며 null이면 기간 제한이 없다. 마감 시각부터 투표·새 의견을 거절하고 읽기는 허용한다. 기존에 저장된 의견의 동일 전송 번호 재시도는 원래 ID를 돌려준다.

이번 범위에는 주제 수정/삭제, 의견 수정/삭제, 별도 인기 점수·승패·타이머가 없다.
차후 정책 추가 시 원문/답글 관계와 회원 탈퇴 정책을 함께 검토한다.
