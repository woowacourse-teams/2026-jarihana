## ADR 운영

되돌리기 어렵거나 영향 범위가 넓은 기술 결정은 적극적으로 ADR로 남긴다.

ADR 우선 대상:

- 데이터베이스와 마이그레이션 도구
- 인증·인가 구조
- 외부 연동 방식
- 메시징 또는 비동기 처리
- 캐시 도입
- API 호환성 정책

ADR에는 배경, 최종 결정, 검토한 대안, 장단점과 후속 작업을 기록한다.

### 번호 매기기

번호는 저장소 전체에서 하나만 쓴다. 새 ADR을 열기 전에 [ADR 목록](../adr/README.md)과 열려 있는
`docs/` 브랜치를 함께 확인한다. 목록만 보면 다른 브랜치에서 이미 쓰고 있는 번호를 못 본다.

번호가 겹친 채로 두 브랜치가 살아 있으면 **나중에 병합하는 쪽이** 파일 이름과 본문 참조를 함께
고친다. 이미 병합된 ADR의 번호는 바꾸지 않는다. 다른 문서의 링크가 깨지기 때문이다.

산문에서 ADR을 가리킬 때는 번호와 링크를 함께 쓴다. 번호만으로는 이미 중복된 0002를 가릴 수 없다.

아직 병합되지 않은 ADR을 링크할 때는 [ADR 목록](../adr/README.md)의 "병합 대기 중인 ADR"에
함께 적는다. 그러지 않으면 그 링크가 왜 깨져 보이는지 읽는 사람이 알 수 없다.

## 실행 환경과 저장소별 정보

### 실행 환경

- 공유 개발 서버를 별도로 두지 않는다.
- 애플리케이션 실행 환경은 로컬과 운영만 사용한다.
- 로컬 개발은 `local` 프로필, 운영 배포는 `prod` 프로필을 사용한다.
- 별도 `dev` 또는 `staging` 프로필과 환경은 팀의 새 결정 없이 추가하지 않는다.

### 실제 저장소에서 확인할 정보

이 문서를 실제 저장소에 적용할 때 다음 정보는 저장소의 실행 가능한 파일을 기준으로 확인한다.
검증된 값은 필수 로딩, 실행 워크플로 또는 명령 정보처럼 AI 로더가 작업을 수행하는 데 필요한
운영 정보일 때만 `AGENTS.md`에 기록하고, 컨벤션 본문으로 중복하지 않는다.

- `build.gradle` 또는 `build.gradle.kts`의 Java 및 Spring Boot 버전
- 소스 트리의 base package와 주요 기능 패키지
- Gradle Wrapper에서 제공하는 빌드·테스트·실행 task
- `local` 프로필의 데이터베이스 실행법과 필수 환경 변수
- `prod` 프로필의 필수 환경 변수
- 애플리케이션 health check 경로
- 코드 포맷터와 정적 분석 명령

빌드와 테스트는 시스템 Gradle보다 저장소의 Gradle Wrapper를 우선 사용한다. 실제 파일에서 확인되지 않은 값은 추측해서 적지 않는다.

## 컨벤션 변경

- 컨벤션 변경은 PR에서 변경 이유와 영향을 설명한다.
- 코드와 문서가 함께 바뀌어야 하면 같은 PR에 포함한다.
- 확정 규칙은 해당 분야의 소유 모듈에서만 수정한다.
- 파일 소유권이나 라우팅이 바뀔 때만 `team-convention.md`를 수정한다.
- 필수 로딩, 우선순위, 작업 흐름이 바뀔 때만 `AGENTS.md`를 수정한다.
- 보류 제안은 `convention-review.md`에 남기며 수락 전에는 적용하지 않는다.
- 파일명이나 소유권이 바뀌면 README, 인덱스와 AGENTS 링크를 함께 갱신한다.
