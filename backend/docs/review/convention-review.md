# 자리하나 보류된 컨벤션 검토 항목

이번 검토에서 확정된 결정은 해당 소유 모듈에 반영한다. 파일 소유권이나 라우팅이
바뀔 때만 `team-convention.md` 인덱스를 갱신한다. 루트 `AGENTS.md`는 컨벤션
본문을 중복하지 않고 인덱스와 선택된 모듈을 AI가 로딩하도록 안내한다.

아래 항목은 의도적으로 결정을 미룬 내용이다.
이 문서는 지침 우선순위에 포함되지 않으며 현재 개발을 막거나 구현 범위를 넓히는 기준으로 사용하지 않는다.
사용자가 다시 요청하거나 실제 요구사항·장애·성능 문제가 확인될 때만 재검토한다.

## API

- 표준 오류 응답의 세부 필드와 필드 검증 오류 구조
- API URL 버전과 호환성·폐기 정책
- offset 페이지네이션의 기본 정렬, 동률 정렬 키, 최대 페이지 크기와 검색 필터 세부 규칙

목록 조회 방식은 offset 페이지네이션으로 확정되어 있다. 위 세부 값이 기능 요구사항에 없으면 전역 규칙을 임의로 만들지 않는다.

## 날짜와 시간

- 저장 및 표시 시간대
- 외부 API의 날짜·시간 문자열 형식

도메인 타입은 `LocalDate`와 `LocalDateTime`, 현재 시간 제어는 주입한 `Clock`을 사용하는 것으로 확정되어 있다.

## 브랜치와 데이터베이스 마이그레이션

- 긴급 수정 사항을 `main`과 `develop`에 동기화하는 구체적인 절차

브랜치 보호·Squash merge와 `ddl-auto: validate`는 이미 확정된 규칙이다.

## 트랜잭션과 비동기 처리

- 이벤트 발행 시점과 발행 실패 복구 방식

단순 조회에는 트랜잭션을 사용하지 않고, 변경 또는 명시적 일관성이 필요한 유스케이스에만 트랜잭션을 적용한다는 원칙은 확정되어 있다.

## Soft delete

- 관리자·감사 조회에서 삭제 데이터를 포함하는 방식
- 삭제 복구 기능과 물리 삭제 보존 기간

`LocalDateTime deletedAt` 사용과 일반 조회에서 삭제 데이터 제외는 확정되어 있다.
PK 이외의 unique 제약이 실제로 필요해지면 구현 전에 충돌 정책을 사용자에게 다시
알리고 결정한다.

## JPA

- Hibernate 프록시와 실제 클래스의 동일성 비교를 위한 특수 처리
- 연관 컬렉션의 초기화 및 외부 노출에 대한 추가 규칙
- 모임장 위임에서 사용하는 그룹 행 비관적 락과 DB 제약의 역할 분담
- 활동 중인 그룹의 `LEADER` 1명 불변식을 부분 unique 인덱스 등 DB 제약으로도
  보장할지, 애플리케이션 트랜잭션과 비관적 락으로만 보장할지
- `findActiveByGroupId`처럼 시간에 따라 계산되는 활성 상태 판단을 Repository의
  조회 조건으로 둘지, Service/Application 계층에서 도메인 상태를 계산해 선별할지

현재는 프록시 특수 처리를 추가하지 않는다. 문제가 재현될 때만 다시 검토한다.
모임장 위임은 현재 그룹 행 비관적 락으로 직렬화하지만, 이 구현을 모든 동시성 처리의
기본 원칙으로 확정하지 않는다. `LEADER` 유일성의 DB 보강 방식은 PostgreSQL 부분
unique 인덱스의 이식성, 종료 그룹의 보존 정책, 락과 제약의 중복 비용을 검토한 뒤 결정한다.
활성 상태 판단의 책임은 DB 필터링 효율과 잠금 대상의 정확성, 도메인 규칙의 응집도,
테스트 용이성 및 조건 중복 가능성을 함께 비교한 뒤 결정한다. 결정 전까지 현재 구현을
전역 설계 원칙이나 다른 상태 조회의 선례로 사용하지 않는다.

이 문서에 남긴 항목 외의 기존 제안은 현재 검토 및 구현 범위에서 제외한다.
