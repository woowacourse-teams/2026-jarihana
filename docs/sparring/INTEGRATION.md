# 토론해요 서비스 통합

## 현재 참여 흐름

1. `/sparring`에서 진행 중인 주제를 가로 카드 목록으로 탐색하고 제목을 검색한다.
   마감된 토론은 결과를 포함한 별도 목록에서 보여준다.
2. 로그인한 회원이 ‘토론 만들기’에서 주제(80자), 서로 다른 두 생각(각 32자),
   선택 설명(240자), 선택 대표 이미지와 필수 마감일을 등록한다.
   마감일은 서울 날짜 기준 내일을 기본값으로 하며 내일/3일/1주일/15일 퀵 선택과
   공통 달력을 제공한다. 선택한 날의 마지막 시각을 서버에 전송한다.
3. 상세에서 양측 주장 또는 입력용 캐릭터를 눌러 편을 고른다. 투표는 회원당 주제별
   하나이며 편을 바꿀 수 있다. 글 수는 투표수에 영향을 주지 않는다.
4. 캐릭터의 말풍선에 160자까지 작성한다. 저장된 한마디는 캡슐로 포장되어 해당 편
   호스를 지나 통으로 발사된다. 전송 연출이 끝나기를 기다리지 않고 다음 글을 쓸 수 있다.
5. 새 일반 메시지는 파이프 말풍선으로 표시한 뒤 미끄럼틀의 지난 대화에도 들어간다.
   닫힌 캡슐이 내려와 열리면 실제 3D 캐릭터가 걸어나와 말풍선으로 대화한다.
   최대 네 캐릭터와 말풍선을 동시에 표시하며 포인터를 올린 말풍선을 앞으로 가져온다.
6. 나온 캐릭터의 말풍선을 누르면 해당 의견을 받아치기 대상으로 선택한다.
   전송한 답장과 원문의 캡슐은 충돌하고, 충격 중심부터 통 안의 캡슐이 흔들린다.
   맞붙은 캡슐이 함께 미끄럼틀을 굴러 내려와 열린 뒤 두 의견의 대치로 이어진다.
7. 마감된 주제는 결과를 볼 수 있지만 새 투표와 메시지를 저장할 수 없다.
   ‘모인 대화’ 패널과 수동 재생 제어는 현재 화면에서 숨긴 상태다.

실패 시 초안을 유지하며 저장에 실패한 메시지는 동일 requestId로 재시도한다.
초안은 페이지 메모리에만 있고 새로고침이나 탭 종료까지 보존하지 않는다.
삭제·수정·신고·운영 제어는 이번 참여 흐름에 포함하지 않는다.

## 투표와 연출의 의미

통 안에는 실제 인원과 별개인 대표 캡슐 240개가 있다. 처음 진입할 때 투표 비율로
색상을 구성하고, 이후 투표 변경은 기존 캡슐의 색을 즉시 바꾸지 않는다.
양측 파이프의 공급 비율과 기존 캡슐의 교체를 통해 새 투표 비율에 점차 가까워진다.
투표는 있지만 글이 없는 편도 캡슐을 공급한다.

파이프의 반복 공급과 지난 대화 재생은 새 접속자·투표·글을 만들지 않는다.
실시간 일반 글은 파이프의 말풍선을 보여줄 시간을 확보한 뒤 미끄럼틀 재생 대기열에
우선 포함한다. 받아치기의 충돌 연출과 일반 대화 재생은 구분한다.
화면 밖에서는 움직임을 멈추고 모션 감소 설정에서는 이동 연출을 줄인다.

## 렌더링과 서비스 경계

React가 목록·등록·인증·HTTP·SSE와 계약 파싱을 소유한다.
Three.js + Cannon 렌더러는 같은 출처의 전용 iframe 문서에서 실행한다.
부모는 메시지의 source, origin, 스키마를 확인하고 공통 API 클라이언트로 요청한다.
iframe에는 인증 토큰을 전달하지 않으며 주제 이동 시 문서와 SSE를 정리한다.
새 npm/Gradle 의존성이나 런타임 외부 CDN을 추가하지 않는다.

미끄럼틀과 입력창의 인물은 원본 이미지의 크루/코치 외형을 참고한 3D 부품·관절 모델이다.
원본 모델을 복원한 것은 아니므로 완전히 동일하다고 볼 수는 없다.
회색 니트·배낭과 검정 옷·민트 명찰, 얼굴과 머리 형태를 재현하고 재질별 인스턴스로 묶는다.
통 안 다수 캡슐의 인물 및 기존 받아치기 VS는 이미지 아틀라스를 사용한다.
확장된 회원 유형도 서버 응답과 브리지에서 수용하며, 크루/코치 외에는 기존 캐릭터 변형을 선택한다.

## 실시간·저장·이미지 계약

- 쓰기 요청은 기존 인증과 CSRF 검증을 거친다. 조회와 SSE의 공개 경로는 GET만 허용한다.
- 주제 행 잠금으로 투표 변경·의견 작성·revision 증가를 직렬화한다.
- requestId는 주제+작성자 단위로 유일하다. 동일 내용의 재시도에는 기존 저장 결과를 반환한다.
- SSE는 활성 주제별 DB revision을 1초마다 조회하고 변경된 revision을 알린다.
  초기·재접속 시 HTTP로 현재 투표와 마지막 수신 ID 이후의 글을 가져온다.
- 15초 heartbeat, 120초 연결 교체, 프로세스당 최대 500 연결을 사용한다.
  전달 지연에는 폴링 주기와 네트워크·조회 시간이 더해진다.
- 대표 이미지는 기존 업로드 검증과 lifecycle을 사용한다. 자기 소유의 사용 가능한 업로드만
  토론 생성 시 연결하며 다른 모임·토론에 이미 연결된 이미지는 재사용하지 않는다.
- 새 토론의 마감일은 요청과 서비스에서 필수로 검증한다. 기존 데이터의 closes_at은 nullable이며
  마감일 없는 기존 행을 자동으로 마감시키거나 임의 날짜로 덮어쓰지 않는다.

## 파일과 DB 변경

- `backend/.../sparring/`: 주제·투표·메시지·조회·SSE
- `frontend/src/features/sparring/`: API 계약과 iframe/SSE 브리지
- `frontend/src/pages/sparring/`: 목록·토론 만들기·상세
- `frontend/public/sparring-arena/`: 3D 렌더링·물리·대화·입력 연출
- `V14__sparring.sql`: 주제·투표·메시지와 인덱스
- `V15__sparring_deadline.sql`: 마감일 컬럼
- `V16__sparring_representative_image.sql`: 기존 이미지 테이블의 토론 연결 범위 확장

V11~V13은 최신 develop의 회원·푸시·공지 마이그레이션이 사용한다.
과거 격리 데모 DB에 이전 번호의 토론 마이그레이션을 적용했다면 해당 DB의 이력은
현재 정식 버전과 다르다. 운영 DB에 과거 데모 SQL을 적용하거나 임의 repair하지 않는다.
이 PR의 검증은 Testcontainers의 격리 DB에서 수행한다.

현재 PR의 검증 결과는 PR 본문을 기준으로 한다. [QA.md](QA.md)는 이전 통합 시점의
검증 기록이며 현재 코드 전체에 대한 승인이나 운영 검증을 뜻하지 않는다.
