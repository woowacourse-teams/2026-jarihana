## 실제 수신 검증

임시 키와 격리 DB로 실제 Spring 서버를 실행하고 Chrome의 PushManager 구독을 등록했다.
실제 신청 API로 모임장 알림·전송 대기를 생성한 뒤 백엔드 워커가 외부 제공자로 전송했다.
Chrome SW가 푸시를 받고 비공개 내용 API를 조회한 뒤 해당 알림 ID·제목으로 브라우저 알림을 생성했다.
`ServiceWorkerRegistration.getNotifications()`로 이를 확인했다. DB의 전송 상태도 `ACCEPTED`를 확인했다.
운영 데이터·키·계정은 사용하지 않았다.

로그아웃 이후 해당 서버 구독이 비활성이고 Chrome PushSubscription이 제거된 것을 확인했다.
다른 브라우저 구독을 모두 해제하는 검증으로 바꾸지 않고 현재 구독 ID만 확인한다.
이 검증은 OS 알림 센터의 시각적 표시나 사용자가 실제 알림을 클릭한 동작을 대신하지 않는다.
알림 클릭 내부 경로는 실제 백엔드 브라우저 테스트로, SW notificationclick 처리는 기존 이벤트 테스트로 검증했다.

처음 자동화의 비공개 브라우저 컨텍스트에서는 `Registration failed - permission denied`로 실패했다.
일반 임시 Chrome 프로필로 변경해 구독·수신을 확인했다. 이후 발견한 테스트 모임 이름 충돌도
격리 데이터 이름을 실행별로 구분해 해결했다. 프로덕션 인증이나 푸시 검증을 우회하는 코드는 추가하지 않았다.

`npm run test:push:local -- --real-provider`로 새 DB·키를 생성하는 재현 스크립트 자체도 실행해 3건 통과를 확인했다.
실행 후 스크립트가 생성한 백엔드·컨테이너·Chrome 프로필·키 파일을 정리한다.

## 변경한 배포 준비

- dev/prod workflow와 Compose에 기능 활성화·VAPID 설정을 연결했다. 기본값은 기능 비활성이다.
- 프론트 workflow에 SW·manifest·아이콘 산출물 확인과 MIME·재검증 캐시 헤더 업로드를 추가했다.
- 실제 배포판의 SW Minimum TTL=0, 인증 API 캐시 금지와 쿠키·쿼리 전달, SQL 적용·배포 순서를 운영 문서에 기록했다.

## 아직 확인하지 않은 항목

사용자는 HTTPS 개발 주소와 실기기가 아직 없으므로 로컬 검증 결과부터 정리하기로 했다. 실기기 검증은 추후 진행한다.

- 실제 macOS Safari와 iPhone·iPad 홈 화면 앱의 구독·수신·로그아웃·OS 알림 클릭
- Chrome의 실제 권한 팝업 선택과 OS 알림 센터 클릭
- 공유·운영 DB의 수동 SQL 적용, GitHub 환경 값 등록, 실제 S3/CDN 헤더·함수 연결과 배포 리허설
- 기존 브라우저 테스트 실패 10건(보류)

이 결과를 모든 지원 환경과 실제 배포의 완료로 해석하지 않는다. 따라서 6단계 전체 완료와
임시 문서 삭제는 모든 구현과 필수 검증을 마친 뒤 처리한다.

## 모임 이름 표시와 상세 이동 변경 검증

- 모든 사건의 `target.kind`는 `GROUP_DETAIL`이며 `/groups/:groupId`로 이동한다.
- 알림 본문은 현재 모임 이름과 사건 내용을 함께 표시한다. 목록 단위 일괄 조회이며 DB 스키마 변경은 없다. 없어진 모임은 `삭제된 모임`으로 표시한다.
- 프론트엔드는 이전 `MY_REGISTRATIONS`·`LEADER_REGISTRATIONS` 응답도 모임 상세로 해석한다. 알림 소유권과 모임 접근 가능 여부는 기존 서버 API가 검증하며, 리더 변경·모집 삭제 때문에 공개 상세 이동을 막지 않는다.
- `NotificationInboxAcceptanceTest` 49건 통과. 5개 사건의 이름 표시·목적지, 없어진 모임의 기록 유지, 기존 소유권·읽음·삭제 계약을 포함한다.
- 관련 Jest 5건, lint 경고 0건, 프로덕션 빌드와 알림 Chromium 테스트 12건 통과. 360·768·1440px 및 알림함 페이지·Drawer axe 검증을 포함한다.
- 격리 PostgreSQL·실제 Spring API 통합 테스트 2건 통과. 이 실행은 외부 푸시 제공자 테스트 1건을 생략했으며 기존 PC Chrome 수신 검증 결과와 구분한다.

모임 이름 표시·상세 이동과 문서 정리까지 반영한 working tree를 재검증했다. 커밋·push·실제 배포는 수행하지 않았다.

- Java21 전체 테스트 강제 재실행: 80 suite / 630건 통과, 실패·오류·생략 0건.

- 프로덕션 빌드와 핵심 Chromium 21건 통과. 보류한 기존 브라우저 실패 10건은 실행하지 않았다.
- 새 격리 DB·키와 일반 Chrome으로 `test:push:local -- --real-provider`를 다시 실행해 통합 3건 통과.
- dev/prod workflow·Compose 6개 YAML 파싱, 더미 환경 값의 Compose 렌더링과 VAPID 연결 통과. PWA 업로드 명령 6건을 로컬 AWS 대역으로 확인했으며 실제 AWS 변경은 없다.
- 운영 점검 SQL의 `localtimestamp` 비교는 DB 연결 시간대에 의존하므로 서울 기준 `timezone('Asia/Seoul', now())` 비교로 수정했다.
- 로컬 구현·자동화 검증은 통과했지만 Safari·iPhone·OS 알림 클릭·실제 배포 검증은 남아 있다. 진행표와 검증 기록은 유지한다.
