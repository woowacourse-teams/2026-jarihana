# ADR 0002. 알림함과 Service Worker

## 알림함을 먼저 보여준다

헤더의 종 버튼은 공통 Drawer를 연다. 독립된 `/notifications` 페이지는 두지 않고,
`/notifications/open/:id`는 알림 확인 후 관련 화면으로 이동하는 진입점으로 유지한다.
열기만으로 읽음 처리하지 않는다. 전체 읽음은 서버 응답 후 목록을 다시 조회하고 행을 유지한다.
삭제는 서버가 성공한 뒤 240ms 동안 오른쪽으로 사라지고 행을 제거한다. 실패하면 행과 재시도 안내를
남긴다. 이동 효과를 줄이는 설정에서는 바로 제거한다. 키보드 포커스는 다음 알림이나 목록 제목으로 옮긴다.

조회 캐시는 회원 ID와 인증 세션 버전으로 구분한다. 로그아웃·계정 변경 때 이전 조회를 취소하고
이전 캐시를 제거한다. 예를 들어 A가 로그아웃하고 B가 로그인하면 A의 목록을 잠깐 표시하는 일을 막는다.
이는 브라우저 메모리 정리이며 DB에 저장된 A의 알림은 유지한다. 소유권 검사는 서버가 수행한다.

## 브라우저마다 구독한다

푸시 권한 요청은 사용자가 `켜기`를 누를 때 시작한다. 로그인이나 알림함 열기만으로 권한을 묻지 않는다.
브라우저가 만든 구독을 서버에 등록하고 서버 응답의 ID·generation으로 SW의 수신 연결을 활성화한다.
크롬과 사파리는 별개의 구독이다. `끄기`와 로그아웃은 현재 브라우저에만 적용한다.
iPhone·iPad에서는 홈 화면에서 실행하도록 안내하고, 미지원 환경에서도 알림함은 사용할 수 있다.

## 앱을 닫아도 SW가 수신한다

`public/sw.js`는 앱 번들과 별도로 `/sw.js`에 배포한다. SW는 푸시의 알림 ID·구독 ID·generation을
확인하고 로그인 쿠키를 포함해 서버의 비공개 내용 API를 조회한다. 조회가 실패하면 승인 결과 같은
상세 내용 없이 일반 안내만 표시한다. 클릭은 임의의 payload URL 대신 `/notifications/open/:id`로 이동한다.
앱은 로그인 복귀와 알림 소유권을 확인한 뒤 사건별 목적지로 이동한다. 새 신청은 신청 관리, 새 참여는 참여자 관리, 승인은 마이페이지의 해당 참여 모임, 모든 미승인은 해당 미승인 신청으로 연결한다. 관리 화면은 현재 모임장 여부를 확인한 뒤 읽음 처리한다. 승인·미승인은 읽음 처리 후 본인 목록 캐시를 갱신하고 마이페이지로 이동한다. 해당 탭과 항목을 다음 페이지까지 찾아 스크롤·키보드 focus·잠깐 강조를 제공한다. 대상이 없으면 탈퇴·기록 삭제 가능성을 안내한다. 미승인은 신청 ID로 구분하므로 같은 모임의 다른 신청을 잘못 강조하지 않는다.
알림함 본문은 현재 모임 이름과 사건 내용을 함께 보여준다. 구체적인 경로는 알림 API 계약에서 관리한다.
대상이 없어졌거나 접근 권한이 바뀌면 알림함으로 돌아갈 수 있게 안내한다.

SW는 IndexedDB에 회원 ID·구독 ID·generation·수신 활성 여부·로컬 revision만 저장한다.
endpoint, 암호화 키, 알림 본문과 로그인 토큰을 저장하지 않는다. 알림 API 응답과 앱 페이지를
캐시하지 않으며 `fetch` 가로채기도 하지 않는다. 따라서 이번 PWA는 오프라인 조회 기능을 제공하지 않는다.

## 로그아웃과 뒤늦은 응답의 순서를 맞춘다

로그아웃은 SW의 수신 중단과 기존 표시 알림 닫기가 끝났다는 응답을 먼저 기다린다.
그 뒤 현재 구독 ID·generation을 로그아웃 API에 보낸다. 서버 처리에 실패하면 로그인 상태를 유지하고
재시도를 안내하며 로컬 푸시는 중단 상태로 남긴다. 성공하면 브라우저 구독도 해제한다.
같은 브라우저의 다른 탭도 SW의 공유 상태와 인증 변경 메시지를 통해 같은 상태를 확인한다.

서버의 generation은 구독 연결의 버전이고, SW의 revision은 로컬 작업 순서를 확인하는 별도 숫자다.
내용 조회 중 로그아웃이 끝나면 revision이 달라져 늦은 응답을 표시하지 않는다. 구독 등록이나 키 교체도
확인했던 revision이 유지될 때만 연결을 바꾼다. 알림 표시와 수신 중단은 직렬 처리하므로 표시 중이었다면
그 표시를 마친 뒤 닫고 중단 응답을 보낸다. 중단 확인에 실패하면 로그아웃을 완료했다고 표시하지 않는다.

## 배포와 검증 경계

SW는 자동으로 `skipWaiting`하지 않는다. 기존 탭을 닫아 새 SW가 활성화된 뒤 저장된 연결 상태를
읽는다. 앱·SW 메시지 protocol과 저장 형식을 변경할 때는 이전 버전과의 호환성을 검토해야 한다.
`/sw.js`를 SPA HTML로 되돌리지 않고 JavaScript로 제공하며 캐시 갱신 정책과 manifest·아이콘 경로를 확인한다.
배포 경로와 환경별 검증 상태는 [웹푸시 운영 가이드](../../../backend/docs/operations/web-push.md)를 따른다.

Jest의 SW 이벤트 재현과 Chromium의 실제 SW·IndexedDB 검증은 외부 푸시 제공자의 전달 성공을
보장하지 않는다. 실제 제공자 수락, Chrome·Safari·홈 화면 앱의 수신·클릭, 배포 경로는 별도 검증한다.
