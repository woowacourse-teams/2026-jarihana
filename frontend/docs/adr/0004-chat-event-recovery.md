# 프론트엔드 ADR 0004. 채팅을 모달로 열고 이벤트와 이력을 함께 관리한다

- 상태: 채택, 로컬 구현 / 운영 적용 대기
- 결정일: 2026-10-25
- 보완일: 2026-10-26
- 관련 문서: [백엔드 ADR 0028](../../../backend/docs/adr/0028-durable-group-chat-and-postgres-notify.md), [공통 채팅 계약](../../../docs/chat-implementation-contract.md)

## 배경

모임을 둘러보거나 상세 내용을 읽다가 채팅을 열고 다시 하던 화면으로 돌아가는 흐름을 원했다.
초기 독립 채팅 페이지에서 현재 페이지 위의 모달로 바꿨고, 기존 사이트의 카드·입력·글자 크기를
따르도록 조정했다. 여러 모임과 여러 창에서 들어오는 이벤트는 같은 규칙으로 병합한다.

## 화면 구조의 선택

| 대안 | 장점 | 단점·한계 | 결정 |
| --- | --- | --- | --- |
| 독립 채팅 페이지 | 넓은 대화 영역, 단순한 라우트 | 탐색·모임 상세 화면을 떠나야 함 | 초기 시안에서 변경 |
| **현재 페이지 위의 모달** | 배경 검색 조건·스크롤을 유지하고 바로 복귀 | 포커스·뒤로가기·중첩 overlay 관리 필요 | 채택 |
| 모임 상세의 채팅 탭 | 해당 모임 안에서 찾기 쉬움 | 다른 모임과 오가기 어렵고 콘텐츠 탭과 동작이 달라짐 | 상세 사이드바 진입점으로 변경 |
| 별도 모임 정보 Drawer | 채팅 안에서 정보 확인 | 상세 화면과 정보·이동 UI가 중복됨 | 대화 헤더의 상세 링크로 정리 |

전역 헤더의 채팅 아이콘은 목록을 연다. 모임 상세에서는 구성원에게 사이드바 마지막에 채팅 버튼을
보여 주며, 좁은 화면에서는 모집 정보 액션 영역 마지막에 둔다. 마이페이지 모임 카드의 채팅 버튼은 제거했다.
대화 헤더의 모임명·참여자 영역을 누르면 모달을 닫고 해당 상세로 이동한다.

### URL과 상태 소유권

| 상태 | 저장·관리 위치 | 수명 |
| --- | --- | --- |
| 모달 열림·선택한 방 | URL의 `chat=inbox` 또는 `chat=모임ID` | 링크·브라우저 이동에 반영 |
| 모임 목록·확정 메시지·읽음 | 회원 ID와 인증 세션 버전으로 구분한 React Query 캐시 | 채팅 세션 종료·계정 변경 때 정리 |
| 방별 입력 초안 | `ChatSession` 메모리 | 같은 모달에서 방을 이동할 때 유지 |
| 실패 전송 원문·UUID | 해당 방 메시지 캐시 | 같은 채팅 세션에서 재시도 |
| 목록 너비 | `ChatSession` 상태 | 모달을 닫으면 초기화 |
| WebSocket 연결 | `useChat` effect | 모달이 열려 있을 때 연결, 현재는 방 변경 때도 재연결 |

`ChatLink`는 배경 pathname·검색 조건·hash를 유지한다. 처음 열 때 history 항목을 추가하고
열린 모달 안에서 방을 바꿀 때는 replace한다. 닫기는 `chat`만 제거하며 배경 스크롤을 유지한다.
기존 `/chat`, `/chat/:roomId`는 `/home` 위의 모달로 연결한다.

현재 연결 effect는 선택한 방에 의존한다. 방 이동 때 연결을 다시 만드는 비용이 있으며,
모달 밖에서도 계속 수신하거나 연결을 유지하려면 연결 소유권을 별도 provider로 옮기는 후속 작업이 필요하다.
현재 헤더는 진입점이며 모달을 닫은 상태의 상시 미확인 수 구독은 구현 범위에서 제외했다.

### 디자인 결정

| 항목 | 최종 선택 | 이유 |
| --- | --- | --- |
| 데스크톱·모바일 | 데스크톱 중앙 모달, 모바일 전체 화면 | 대화 폭을 제한하고 작은 화면의 읽기 공간 확보 |
| 글자 크기 | 사이트 공통 토큰 | 채팅만 크게 보이던 차이 해소 |
| 목록 카드 | 마이페이지처럼 왼쪽 대표이미지, 세로 중앙 본문 | 기존 카드와 배치 통일. 이름·최근 메시지·시간·참여자 정보 유지 |
| 선택·hover | 호버는 얕은 그림자, 선택은 더 진한 두 겹 그림자 | 테두리 색을 유지하면서 호버·선택·종료 상태 구분 |
| 종료된 모임 | 회색 사진·배경과 종료 배지 | 선택 상태와 별도로 읽기 전용 상태 표시 |
| 검색·작성 | underline 입력, 한 줄부터 늘어나는 작성창 | 기존 페이지의 입력 스타일과 통일 |
| 대화 본문 | 내부 최대 너비 제한을 없애고 일정한 작은 좌우 여백 | 모달 안의 불필요한 여백 축소 |
| 전환 | 대화 패널에 View Transition, reduced-motion 대응 | 방 이동을 부드럽게 하고 배경 상세 애니메이션과 분리 |

모달은 기존 공통 overlay의 포커스 복귀·Esc·배경 클릭 동작을 사용한다.
채팅 중에는 배경 상세의 named snapshot을 제외해 두 전환이 겹치지 않게 한다.
세부 토큰과 배치는 [DESIGN](../../DESIGN.md), [구현 맵](../IMPLEMENTATION_MAP.md)이 관리한다.

## 실시간 수신과 복구

`@stomp/stompjs` 7.5.0으로 `/api/ws/chat`에 연결하고 `/user/queue/chat-events`를 구독한다.
전송은 공통 HTTP client를 사용한다. 재연결 전 내 정보 요청으로 기존 single-flight 인증 갱신을
거치고 서버의 회원이 현재 계정과 다르면 인증 상태를 다시 확인한다.

| 이벤트 | 화면 처리 |
| --- | --- |
| `MESSAGE_CREATED` | 메시지 ID로 병합, 자신의 낙관적 메시지는 발신자·`clientMessageId`로 치환, 목록 갱신 |
| `READ_STATE_UPDATED` | 본인의 여러 창에 읽음 위치·미확인 수 반영 |
| `ROOM_CLOSED` | 목록과 대화를 종료 상태로 바꾸고 입력 차단 |
| `ROOM_REMOVED` | 목록·이력 캐시에서 제거, 늦은 목록 응답의 재등장 차단 |
| `RESYNC_REQUIRED` | 목록과 열린 방의 이후 메시지를 REST로 동기화 |

평소에는 이벤트로 캐시를 직접 갱신한다. 누락 순번이 보이면 REST로 보충하며,
구독 직후·재연결·온라인 복귀·화면 복귀·활성 화면의 30초 주기에도 DB와 맞춘다.
높은 순번 하나가 먼저 도착해도 그 앞의 빈 구간을 복구할 수 있도록 순번을 다음과 같이 구분한다.

| 값 | 의미 | 갱신 기준 |
| --- | --- | --- |
| `latestSequence` | 알고 있는 방의 최신 저장 순번 | 서버 snapshot·메시지 결과 |
| `syncCursor` | 이후 조회를 시작할 복구 기준 | 최초 이력 snapshot, 연속 이벤트, 끝까지 완료한 catch-up |
| `lastReadSequence` | 사용자가 읽었다고 기록한 위치 | 화면 관찰 후 서버의 단조 증가 갱신 |
| `unreadThrough` | 서버 미확인 수가 반영한 메시지 범위 | 읽음 응답·이벤트의 `latestSequence` |

ID와 순번은 JavaScript 정밀도 손실을 피하려고 10진수 문자열로 다룬다.
최초 이력은 최근 페이지를 읽고 그 snapshot의 마지막 순번을 복구 기준으로 삼는다.
그보다 오래된 대화는 `beforeSequence`로 따로 읽는다.
이후 누락은 `afterSequence` 페이지를 끝까지 따라간다.

예를 들어 복구 기준이 10인데 12번 이벤트가 먼저 오면 12를 화면에 병합하되 복구 기준은 10에 둔다.
REST에서 11 이후를 읽고 병합한 뒤 기준을 옮긴다.
읽음 응답의 미확인 수에 이미 12번이 포함됐다면 늦은 12번 이벤트로 수를 다시 올리지 않는다.

이전 이력의 로딩 상태는 방과 요청별로 관리한다. 취소한 요청이 다음 방의 로딩을 막지 않게 하고,
늦은 목록 응답이 더 최신인 메시지·읽음·종료 상태를 덮지 않게 병합한다.
로그아웃·계정 변경 때 소켓·요청·캐시를 정리한다.

## 전송·읽음의 기준과 비용

| 선택 | 장점 | 단점·한계 |
| --- | --- | --- |
| 낙관적 표시 + 동일 UUID 재시도 | 전송 직후 내용을 보여 주고 중복 저장 방지 | HTTP 결과·이벤트·실패 표시의 순서 처리 |
| 실제 화면을 보고 읽음 처리 | 백그라운드 수신으로 미확인 수가 사라지는 문제 방지 | 스크롤·창 포커스·가시성 관찰 필요 |
| 주기적 REST 복구 | 누락한 이벤트를 DB 이력으로 보충 | 활성 사용자 수에 따라 주기적 조회 증가 |
| 목록 전체 페이지 조회 후 검색 | 현재 참여 모임을 한 번에 탐색 | 가입 모임이 많아지면 초기 조회·재동기화 비용 증가 |

읽음 요청은 활성 창에서 대화가 맨 아래에 있고 최신 확정 메시지가 복구 커서와 맞을 때만 보낸다.
종료된 모임은 이전 대화와 읽음 갱신을 허용하되 새 전송을 막는다.
Enter로 전송하고 Shift+Enter로 줄을 바꾸며, 한글 조합 중 Enter는 전송하지 않는다.

실패한 메시지는 원문과 UUID를 유지한다. 소켓으로 저장 결과를 확인한 뒤 늦은 HTTP 실패가 와도
성공한 메시지를 실패로 되돌리지 않는다. 모달을 닫거나 새로고침하면 초안·실패 전송 상태는 사라진다.
지속 보관이 필요해지면 계정별 저장·만료·로그아웃 정리 정책을 함께 정해야 한다.
