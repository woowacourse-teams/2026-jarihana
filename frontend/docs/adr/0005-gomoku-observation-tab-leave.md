# 프론트엔드 ADR 0005. 같은 브라우저의 오목 관전 탭을 함께 퇴장시킨다

- 상태: 채택, 로컬 구현 / 운영 적용 대기
- 결정일: 2026-11-06
- 관련 문서: [오목 관전 API 계약](../../../backend/docs/context/api/endpoints/gomoku-observation.md)

## 배경

한 회원이 같은 오목방을 여러 탭에서 관전하면 서버는 탭마다 입장을 따로 기록한다. 각 탭은 자신의
`requestId`로 입장하며, 서버가 발급한 `participationId`로 판과 입장 이후의 채팅을 조회한다.
이 구조에서는 한 탭에서 "관전 나가기"를 눌러도 같은 방을 보고 있던 다른 탭은 관전을 계속한다.
버튼을 누르면 같은 브라우저 프로필에서 같은 계정으로 같은 방을 관전하는 탭도 대기실로 보내고자 한다.

## 검토한 대안

| 대안 | 장점 | 비용과 영향 |
| --- | --- | --- |
| 탭별 입장과 브라우저 퇴장 알림 | 현재 입장 API와 탭별 채팅 조회 기준을 재사용하고 알림 범위를 회원과 방으로 제한한다. | 각 탭이 퇴장 요청을 보내므로 알림을 놓치거나 요청이 실패한 탭은 관전을 계속할 수 있다. |
| 같은 브라우저의 탭끼리 입장 공유 | 퇴장 요청 한 번으로 공유한 관전 권한이 모두 종료된다. | 탭 간 입장 키 공유와 재입장 규칙이 필요하다. 탭마다 따로 기록하던 채팅 조회 시작 시점이 합쳐지고, 화면 이동을 위한 종료 감지도 필요하다. |
| 서버에서 회원의 해당 방 관전을 일괄 종료 | 서버가 해당 회원의 입장을 한 번에 종료할 수 있다. | API와 서버 종료 처리가 바뀌고, 회원과 방으로만 범위를 정하면 다른 브라우저와 기기의 관전까지 종료된다. |

## 결정

탭별 입장을 유지하고 `BroadcastChannel`로 퇴장을 알린다. 이번 요구는 같은 브라우저의 관전 화면을 함께
정리하는 것이므로, 기존 입장 API와 채팅 조회 기준을 그대로 사용할 수 있는 첫 번째 대안을 채택한다.

"관전 나가기"를 누른 탭은 서버 퇴장이 성공한 뒤 회원과 방별 채널에 알린다. 알림을 받은 관전 탭은
자기 입장으로 기존 퇴장 API를 호출하고, 성공하면 탭 저장소를 비운 뒤 대기실로 이동한다. 알림은
버튼을 누른 탭에서만 발송하고, 화면 상단의 "대기실"은 해당 탭에서만 관전을 종료한다.

서버는 각 탭의 퇴장을 개별 처리한다. 퇴장에 실패한 탭에는 기존 오류와 재시도를 제공한다. 채널을
사용할 수 없거나 알림을 받지 못한 탭은 사용자가 직접 퇴장할 수 있다.
