# 공통 아바타 시제품

## 확인할 화면

프론트엔드에서 `npm run dev -- --host 127.0.0.1 --port 5175` 실행 후
`http://127.0.0.1:5175/sparring-arena/avatar-lab/index.html`을 연다.
백엔드나 로그인 없이 실행된다. 정적 파일은 기존 경기장 복사 규칙으로 production build에도 포함된다.
서비스 메뉴에는 진입 링크를 추가하지 않았다.

1. 얼굴·머리·눈/눈썹·코/입·안경/옷 탭에서 10개 항목을 독립적으로 고른다. 한 항목을 바꿔도 다른 선택은 유지된다.
   선택지 이미지는 현재 조합에 해당 파츠만 적용한 실제 모델이다. 색상은 이름이 있는 팔레트로 고른다.
2. 되돌리기·다시 하기·처음 모습으로를 확인하고, 접힌 추천 스타일에서 시작해 일부 파츠만 바꿔본다.
3. 서 있기, 걷기, 말하기, 캡슐 자세와 좌우 180도 회전을 확인한다.
4. 검정·흰 오목 말, 32px 프로필 얼굴을 비교하고 256×256 투명 PNG를 받는다.
5. 아래의 실제 토론 경기장에서 캐릭터로 편을 고르고 한마디를 보낸다.
6. 받아치기 구경하기를 눌러 서로 다른 두 외형이 캡슐과 대치 장면에서 유지되는지 본다.

체험 대화와 선택한 스타일은 메모리에만 존재하며 새로고침하면 초기화된다.
이 체험 페이지에는 실제 토론 API, 회원 저장, SSE 연결, 프로필 이미지 교체를 포함하지 않는다.
별도로 `/my` → `/my/avatar`에서 같은 파츠 시안으로 계정별 생성·수정·서버 저장·삭제를 제공한다.
회원 관리 API는 [회원 아바타 계약](../../backend/docs/context/api/endpoints/member-avatar.md)을 따른다.

## 데이터와 렌더링

- `public/sparring-arena/src/avatar-appearance.js`: 버전 1 외형 규격, 허용 파츠·팔레트, 여섯 시작용 조합.
  눈썹·코·입 선택이 없던 초기 버전 1 데이터는 기존 아치형 눈썹·둥근 코·미소를 기본값으로 채운다.
  회원 유형·진영·자세·자산 URL은 외형 데이터에 넣지 않는다. 알 수 없는 버전이나 잘못된 파츠는 기존 외형으로 돌아간다.
- `walking-characters.js`: 기존 관절·보행·입체 부품에 개인별 머리·얼굴형·눈·안경·색상을 적용한다.
  인스턴스별 색을 사용하고 슬롯마다 외형 키를 관리하므로 다른 인물의 자세나 색을 바꾸지 않는다.
- `avatar-brand-sculpt.js`: 회원 아바타 전용 얼굴·머리 조형. 빈 화면의 남자, 홈 그림의 긴 머리 여자,
  토론 편 선택 인물의 공통 비율을 따른다. 둥근 볼·큰 눈·돌출된 코와 풍성한 머리,
  도톰한 손·신발을 사용한다. `long`은 생머리, `flowing`은 굵은 웨이브이며 기존 저장 키를 유지한다.
  아바타의 얼굴·머리·상체에 그림자를 받아 파츠의 부피가 보이게 하고 얼굴 이미지 카메라도 넓힌다.
- `character-sculpt.js`: 기존 곱슬·가르마 외에 단발·긴 머리·어깨 아래로 푼 긴 생머리의 입체 형상을 제공한다.
  가르마와 비슷했던 짧은 머리는 긴 생머리로 교체했으며 초기 `crop` 값도 새 `flowing` 외형으로 읽는다.
  긴 생머리는 앞쪽 두 가닥과 닫힌 입체 뒷머리로 구성해 정면에서도 얼굴·목·어깨 뒤의 머리 면이 보인다.
  민머리는 머리 메시를 생략하며 단발·긴 머리의 앞쪽 끝은 볼 바깥으로 유지한다. 현재 공통 체형과 신발을 사용한다.
- `characters.js`: 기존 캡슐의 이미지 캐릭터는 유지하고, 유효한 `post.appearance`가 있을 때
  같은 입체 모델을 지연 생성한다. 입력·배송·미끄럼틀·대치도 같은 모델을 사용한다.
- `avatar-preview.js`: 같은 모델에서 고정 정면 카메라로 투명 얼굴 PNG를 출력한다.
  프로필·오목 말은 이 이미지를 재사용한다. 캐릭터별 WebGL canvas는 만들지 않는다.
- 최신 경기장의 `chair-duel-visuals.js`는 공통 `walking-characters.js`로 인물을 표시한다.
  아바타는 같은 모델의 선택 외형으로 적용되며 기존 의자 연출·말풍선·모션 감소 동작을 유지한다.
- `avatar-lab/avatar-editor.js` / `avatar-draft.js`: 파츠별 선택·키보드 탭·최대 50회 편집 기록.
  추천 스타일은 시작점이며 임의 조합을 같은 외형 규격으로 전달한다. 미리보기 이미지는 최근 100개만 캐시한다.
- `avatar-lab/demo-room.js`: 실제 `jarihana-sparring` iframe 연결 규약을 구현한 메모리 전용 호스트.
  작성 시 외형을 고정하며 선택 변경으로 과거 글이 바뀌지 않는다. 명령의 출처와 source를 검사한다.

토론의 민트·코랄 색은 캡슐과 말풍선이 담당하며 사용자 옷·피부색을 덮어쓰지 않는다.
모션 감소에서는 편집 미리보기와 기존 경기장 정책에 따라 이동을 생략한다.

## 다음 단계 전에 확인할 범위

- 파츠 선택과 되돌리기, 회원 저장 API는 구현했다. 파츠의 임의 위치·크기 조절, 옷의 형태 변경, DB 버전 이력은 후속 작업이다.
- 헤어·안경·의상은 코드로 조형한 시제품이며 최종 자산의 파츠 결합 규격은 확정하지 않았다.
- 데스크톱 WebGL과 390px 반응형은 확인하되, 실제 저사양 모바일 GPU의 프레임·발열·메모리 수치는 별도 측정한다.
- 현재 토론 캡슐은 다수의 커스텀 3D 모델을 동시에 표시할 수 있다. 출시 전 캡슐 내부 전용 간소화 모델과
  파츠별 draw call·지오메트리 예산을 정해야 한다.
- PNG 데이터 생성과 256×256 RGBA 파일은 확인했다. 내장 브라우저의 다운로드 완료 이벤트는 응답이 없어
  자동 확인하지 못했다. 일반 브라우저의 파일 저장 동작은 별도 확인이 필요하다.
