# 득템하나? 상점과 구매 연결

## 화면

공개 `/shop`은 밝은 콘솔 스타일 상품 진열대와 3D 입어보기를 제공한다.
전체·아바타 꾸미기·프로필 꾸미기만 두며 보관함과 소지품 전용 탭은 없다.
보유 상품은 가격 대신 보유 상태를 표시한다. 모바일은 상품과 미리보기 사이의 포커스를 이동한다.

체험 상점은 1,200P와 모자 하나로 시작한다. 예시 상품 11개(아바타 9, 프로필 2)이며
딸기우유 비니·버터 버킷햇·크림 소풍 가방·꾸벅 곰돌이 프레임을 추가했다.
새 모자·가방은 공용 3D 파츠를 조합한다. 입어보기는 편집기나 저장 API 없이 동작한다. 프로필 프레임은 일러스트 미리보기다.
체험 구매·착용은 메모리에만 저장하며 새로고침·계정 변경 시 초기화한다. 기존 아바타 선택지는 무료다.

## 실제 API 연결

- 로그인 회원은 #589의 `GET /members/me/points`를 조회한다. 실제 잔액은 체험 잔액과 구분해 표시한다.
  `enabled`는 적립 여부이므로 false여도 실제 잔액을 표시한다. 오류 시 0으로 대체하지 않는다.
- 실제 잔액 조회는 #589에서 제공하는 `usePointSummary`를 상점과 포인트 상세 화면에서 공유한다.
- `GET /shop/products`가 purchasingEnabled=true를 반환하면 로그인 회원은 실제 구매 어댑터로 전환한다.
- 실제 구매는 `POST /members/me/shop/purchases` 한 번으로 처리하고, `GET /members/me/shop`으로
  서버 잔액·보유 상태를 함께 읽는다. 게스트는 체험 상점을 이용한다.
- 오래된 서버의 상품 경로 404와 명시적인 판매 중지만 체험 모드로 처리한다. 기타 오류는 재시도 화면이다.
  실제 구매 실패를 체험 성공으로 바꾸지 않는다.
- 실제 카탈로그는 꾸벅 곰돌이 프레임(600P)과 반짝이는 내 자리(1,800P) 두 종으로 시작한다.
- 구매한 프레임은 상점의 '프로필에 적용' 버튼으로 장착한다. `PUT /members/me/shop/equipment`로
  변경하고 마이페이지는 `GET /members/me/shop/equipment`에서 적용한 프레임을 읽는다.

## 구매 안전성과 코드 경계

`entities/shop`은 응답과 허용 미리보기 값을 검증한다. `features/shop/api.js`는 공통 client의
인증·CSRF·취소 신호를 사용한다. 구매 요청에는 productId/termsVersion/requestId와 확인창을 열 때의 expectedMemberId를 보낸다. 서버가 확인 계정 불일치를 알리면 확인창을 닫고 현재 계정과 잔액을 다시 불러온다.
`demoClient`와 실제 어댑터는 같은 `ShopPreview`를 사용하며 실제 잔액으로 체험 아이템을 차감하지 않는다.

확인창에 UUID를 만들고 결과 불명 재시도는 같은 키를 유지한다. 자동 구매 재시도는 하지 않는다.
서버는 요청 키와 보유 유일성을 함께 확인하므로 화면을 재방문해도 중복 차감하지 않는다.
실제 구매 성공 시 잔액·보유 캐시를 함께 갱신하고 포인트 조회를 다시 요청한다.
화면 상태는 회원·세션·로그아웃 상태별로 분리된다. 아바타 유료 파츠, 소비와 환불은 별도 계약이다.

## 검증

- demo-client: 체험 구매·장착·중복 방지.
- shop-page: 확인·취소·중복 클릭·결과 불명 재시도·보유 가격 숨김·필터·모바일 포커스·실제 구매 안내.
- shop-session: 실제/체험 잔액 구분과 서버 실패 시 구매 차단.
- shop api: 서버 가격 신뢰 경계·스냅샷·취소 신호·판매 중지.
- avatar-preview-update: 3D 입어보기 메시지 검증과 상품 교체 시 모델 재사용.
- 실제 DB 구매는 백엔드 인수 테스트로 확인한다. 브라우저의 실제 로그인·운영 포인트 구매는 미검증이다.
