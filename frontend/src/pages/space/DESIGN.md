# 모임 공간 꾸미기

## 웹 상세의 정면 히어로 (2026-11-09, Active)

- `/groups/:groupId`는 공통 AppShell을 사용한다. 같이해요(`SESSION`)는 대표 사진과 기존 상세 탭을
  표시하며, 예전 아지트 주소로 접속하면 탭과 앵커를 유지해 상세로 이동한다.
- 동아리와 스터디는 본문 위에 아지트 건물을 정면 구도로 배치하고
  배경을 본문까지 연결한다. 미리보기는 정면 사선에서 외벽·지붕·현관을 보여준다.
  스크롤하면 미리보기도 문서와 함께 이동한다.
- 마당 앞쪽과 양옆 가장자리에 낮은 투광등을 배치해 외벽을 비춘다. 실내 조명과 함께
  꾸미기의 조명 설정 및 야외 시간·날씨를 따른다.
- `clubhouse.presentation: "web"`에서는 `RoomCanvas`에 `interactive: false`, `view: "front"`,
  `zoom: 1`, `floorView: "all"`을 전달한다. 편집 도구를 숨기고 포인터·휠·키보드 입력은 웹페이지에 남긴다.
- `놀러가기`는 같은 공간 인스턴스를 유지하며 건물 정면 앞의 1인칭 시점으로 전환한다. `웹 상세로 돌아가기`는
  웹 구도로 복귀하며 공간 배치·작성 중 콘텐츠·음악을 다시 초기화하지 않는다. `/groups/:groupId/space`는 확대 상태로 진입한다.
- 소개·참여자·모집 등은 기존 웹 상세에서 표시한다. 확대 화면에서는 공지·활동 사진을 데스크톱 오른쪽
  패널이나 모바일 하단 시트에서 보고, 채팅은 기존 공통 채팅을 연다. 꾸미기에서는 놀이 메뉴를 편집 도구로 바꾼다.

## 자유 카메라 조작 (2026-11-09, Active)

- 기본 줌은 0.7이다. 꾸미기에 들어갈 때는 건물과 현관을 기준으로 맞추고, 공간 전체 보기에서는 마당까지 담는다.
  확대·축소 버튼과 휠에 제품상 상·하한을 두지 않는다. 곱셈 비율로 조절하며 0·음수·무한대만 방지한다.
- 전체/위에서/층별 보기에서는 빈 공간 왼쪽 드래그로 회전, 오른쪽·가운데 버튼 또는 Shift+왼쪽
  드래그로 화면 이동, 휠로 확대·축소한다. 가구 위에서도 보조 버튼으로 화면을 이동할 수 있다.
- 꾸미기에서 가구 왼쪽 드래그는 기존 배치 동작이다. 이용 모드의 오브젝트는 포인터를 놓았을 때
  클릭을 처리하고, 5px 이상 드래그·취소·포인터 캡처 소실은 기록이나 음악을 열지 않는다.
- 회전·이동은 확대·축소, 화면 크기 변경, 가구/조명 편집, UI 접기에서 유지한다. 시점·층·테마를
  바꾸거나 시점 초기화·공간 전체 보기를 누르면 회전과 이동을 초기화한다. 반복 초기화도 동작한다.
- 1인칭은 캔버스에서 마우스 이동으로 시선을 돌리고, 터치와 3인칭은 드래그로 돌린다. 걷기 시점에서는 Shift로 달리고 Space로 점프할 수 있다. 실제 배치·서버 저장 데이터에 카메라 조작을 넣지 않는다.
- `roomCameraZoom`은 UI에서도 사용하는 순수 줌 규칙, `roomCameraControls`는 지연 로드되는 3D
  카메라 포즈·포인터 처리다. `roomScene`이 가구 배치·걷기와 조작 소유권을 나누고 휠 줌을 React 상태에 전달한다.

## 캔버스 위 무광 유리 오버레이 (2026-11-11, Active)

- `SpaceStudioPage`의 캔버스가 뷰포트 전체를 차지한다. 헤더·왼쪽 메뉴·View 도구·
  하단 카탈로그는 absolute 오버레이이며 별도 grid 행/열이나 외곽 패딩으로 공간을 줄이지 않는다.
- 실제 모임 꾸미기 헤더는 저장·완료 두 동작만 표시한다. 왼쪽 가장자리의 메뉴 버튼은
  공통 기능·가구 등 세로 메뉴를 슬라이드로 펼친다. 기본은 접힘이며 접은 메뉴는
  `inert`와 `aria-hidden`으로 입력 대상에서 제외한다. 선택 패널과 초안은 마운트를 유지한다.
  건물 변경 버튼은 메뉴가 접혀 있어도 테마 선택 패널을 연다.
- 실제 모임의 놀러가기와 꾸미기는 안전 영역을 고려한 12px 가장자리 여백, 48px 정사각 도구, 8px 도구 간격을 공유한다.
  왼쪽 메뉴는 좁은 화면에서도 한 열을 유지하며 `.space-studio__rail`에서 세로로 스크롤한다.
  우선순위는 3D 공간·메뉴 선택·설정 패널이며 주 동작은 저장이다.
- 꾸미기의 오른쪽 위 보기에서 층·보기 방식·카메라 도구를 한 패널에 펼친다. 전체 조명과 건물 외관 전환은 오른쪽에 따로 둔다.
  외관을 다시 숨기면 직전에 보던 시점으로 돌아간다. 실행 취소·다시 실행은 저장·완료 옆에 두고,
  배치 목록은 오른쪽 아래, 가구 카탈로그는 하단 전체 너비를 쓴다. 상세 복귀·저장·완료는 같은 크기의
  정사각형 버튼으로 배치하고, 저장하지 않은 변경은 저장 버튼에 점으로 표시한다.
- 놀러가기에서는 공지·활동 기록·재생목록을 왼쪽 메뉴에, 1·3인칭과 전체 조명을 오른쪽 위 시점 설정에 둔다.
  소리 켜기·끄기와 조작 도움말 버튼은 오른쪽 가장자리에 따로 둔다.
  메뉴와 시점 설정 중 하나만 펼치며 열린 동안 이동을 멈춘다. 모임장에게는 상세로 돌아가기 옆에 꾸미기 버튼을 표시한다.
- 놀러가기에서 마우스로 시점을 조작하는 동안 공통 헤더 뒤로 3D 장면이 비친다.
  포인터를 풀면 원래 배경이 돌아오고 캔버스와 도구 위치는 그대로 유지한다.
- 패널의 스크롤바는 얇은 손잡이와 투명한 트랙을 사용한다. 세로 스크롤이 필요한 패널은
  스크롤바 자리를 미리 확보해 내용이 늘어도 폭이 바뀌지 않게 한다.
- 저장·설정 완료 등 일반 알림은 3.5초 뒤 사라지며 닫기 버튼을 표시하지 않는다. 수정이 필요한
  오류는 내용을 확인할 수 있도록 유지한다.
- 멀티플레이 연결·위치 보정은 자동으로 복구하며, 상단 중앙에 내용 너비의 작은 토스트바로 알린다.
  공통 헤더 아래 HUD 여백을 따르고 좁은 화면에서는 상단 도구 아래에 둔다. 입력·포커스를 가로채지
  않으며 복구 완료는 3.5초 뒤 숨긴다. 접근 거절·로그인 만료처럼 조치가 필요한 안내는 유지한다.
- 놀러가기와 꾸미기의 스튜디오 조작부는 밝은 불투명 면, 얇은 테두리와 부드러운 그림자를 사용한다.
  상세 미리보기 조작부와 공지·활동·도움말 대화창에는 74%의 밝은 중성색과 18px 배경 블러를 사용한다.
  선택 상태는 연한 청록색, 주요 저장 버튼은 짙은 청록색이다. 투명도 줄이기 설정이나 블러 미지원 환경에서는 불투명 면을 사용한다.
- 놀러가기와 꾸미기에서는 하늘의 구름과 별을 월드 좌표에 두고 산과 물의 원경도 실제 카메라 시점을 따른다.
  모임 상세의 외관 미리보기는 기존의 장식 없는 색 배경으로 표시한다.
- 전체 UI와 메뉴·시점 도구를 각각 접고 펼친다. `hidden`으로 가려진 도구는 탭 순서에서 제외하되
  캔버스와 작성 중인 입력은 마운트를 유지한다. 카메라·가구 선택·초안·실행 취소 이력은 보존한다.
- 전체 UI를 숨기면 보이지 않는 가구 편집을 막고, 상시 표시되는 펼치기 버튼 또는 Esc로 복구한다.
  이때 첫 Esc는 걷기 모드를 종료하지 않는다. 공간 오브젝트를 누르면 UI를 다시 펼쳐 기능을 연다.
- 저장 결과 알림과 재생 중인 유튜브 플레이어는 전체 UI 접기와 독립적이다. UI를 접는 동작이
  모임 음악 세션이나 개인 재생 상태를 변경하지 않는다.
- 통합 꾸미기의 모바일 메뉴도 왼쪽에 두고 편집·콘텐츠 패널만 스크롤한다. 체험 스튜디오는
  기존 하단 메뉴를 유지한다. 최소 44px 버튼, safe area,
  포커스 표시와 reduced-motion을 유지한다.

## 잔디 마당과 공중섬 (2026-11-09, Active)

최신 사용자 요청에 따라 아래 건물 주변 복도·인접 건물과 마당 없는 구도를 대체한다.
실내 평면·복층·현관·기존 에셋은 보존하며 7개 테마 모두 같은 외부 지형 규칙을 사용한다.

- `islandLayout.js`가 지형·보행·배치·카메라의 경계 기준이다. 건물 양옆과 뒤쪽에 5m,
  앞에 11m의 땅을 추가하며 절벽 안쪽 1m를 남긴다. 실제 보행 영역은 앞 10m, 나머지 4m다.
- `floatingIsland.js`는 실내 바닥을 덮지 않는 잔디 링, 잔디·흙 단면, 아래로 좁아지는 7m
  바위와 구름을 만든다. 입구 돌길은 지면 위 1cm이며 잔디와 같은 높이로 걸어 다닌다.
  고정 풀·꽃·돌 장식은 보행 경계 밖에만 두고 별도의 보이지 않는 장애물을 추가하지 않는다.
- `마당에 놓기`는 넓어진 앞마당에 에셋을 추가하며 전체 보기로 전환한다. 이후 드래그로
  양옆·뒤쪽 잔디에도 놓을 수 있다. 출입 통로와 절벽 경계는 배치할 수 없다.
- 1·3인칭은 현관에서 마당으로 나가 건물 주위를 돌 수 있으며 절벽 전에 멈춘다.
  실내 벽·가구·계단·복층과 높이 변화에 대한 충돌 규칙은 유지한다.
- 확대 상태의 기본 구도는 실내와 사용 가능한 마당·바위 끝, 전체 보기·위에서 보기·세로 화면은 섬 전체다.
  층별 보기와 배경·조명 설정은 유지한다. 무한 바닥 그림자 면은 두지 않는다.
- 저장은 v9를 유지한다. 기존 v9 배치와 모임 정보·사진·분위기를 읽는 것만으로 바꾸지 않는다.
  v8 이하는 당시 경계로 검증한 뒤 기존 마이그레이션을 적용한다.

  취미 프리셋 모두 세 에셋을 포함한다. 보드는 양면 목재·크림·황동 재질이며 기능 표식은
  카메라를 향한다. 테마와 무관하게 이름과 기능을 유지하며 가구 색·배치·회전은 편집한다.
- 공통 기능 메뉴에서 배치 개수, 선택·추가·열기와 빠진 공통 에셋 추가를 제공한다.
  복원은 기존 가구 위치·ID·내용을 보존하고 비어 있는 실내 바닥에만 추가한다. 공간·160개
  제한을 만족하지 못하면 일부만 추가하지 않고 실패한다. 한 번 실행 취소로 되돌릴 수 있다.
- 저장 v9 계약에 두 kind를 추가한다. 기존 저장은 읽는 것만으로 수정하거나 복원하지 않는다.
  공지·활동·음악은 에셋과 독립적이며 에셋을 삭제해도 가장자리 메뉴로 접근한다.
- 공지 목록과 공개 범위는 기존 모임 공지 API를 따른다. 대시보드는 열람 가능한 최신 공지를
  표시한다. 공지의 작성·수정은 기존 공지 화면에서 한다.
- 이용 중 보드 사진은 연결된 기록을 열고 꾸미기에서는 원본 액자 대신 보드 자체를 선택한다.
  보드 위 기능 표식도 클릭할 수 있다. 모바일은 기존 하단 패널 규칙을 따른다.


## 재사용 가능한 시설 에셋과 여섯 취미 프리셋 (2026-11-09, Active)

- 기존 클라이밍·보드게임에 맛집·밴드·개발·사진을 추가한다. 프리셋은 각기 다른 평면과
  카탈로그 에셋 배치의 조합이다. 맛집은 오픈 키친과 공동 식탁, 밴드는 합주 무대와 믹싱,
  개발은 협업·개인 작업석, 사진은 촬영·편집·전시 공간으로 구분한다.
- 벽·바닥·창·계단·난간·건물에 설치된 조명은 건축 구조다. 서가·암벽·매트·장비 보관함·
  주방·악기·책상·촬영 장비·게시판·독립 조명은 개별 에셋으로 이동·회전·삭제한다.

  평평한 벽·단색 가구, 강한 직사광을 조정한다.
- 모든 테마는 엇갈린 나무 마루와 목재 벽 하단을 공통으로 사용하고 벽 색으로 구분한다.
  전구색 조명, 작은 덩굴 식물, 소파 쿠션·천과 러그의 결로 생활감을 더한다.

- 카메라는 방의 깊이가 드러나는 비스듬한 인형집 시점으로 조정하고 전체 보기와 위에서 보기를 유지한다.
- 저장된 테마 식별자·가구 좌표·사진·기록과 배치 규칙은 유지한다. 거짓 활동 사진은 추가하지 않는다.

## 취미별 아지트 (2026-11-08)

- 기준: 사용자가 제공한 취미별 동아리방 설명과 다이닝·밴드·보드게임 시안.
  첫 구현은 기본 아지트·클라이밍·다이닝 세 가지다. 모임 타입과 취미 테마는 분리한다.
- 공통 방 구조 + 작은 대표 시설 + 함께 앉을 자리 + 직접 고른 활동 기록을 조합한다.
  이름을 가려도 시설과 배치로 취미를 알아볼 수 있어야 한다.
- 기본 아지트는 카페 코너/소파/공동 테이블, 클라이밍은 작은 볼더링 벽/매트/장비와
  벤치/빈백 라운지, 다이닝은 작은 주방과 여섯 자리 식탁이 중심이다.
- 입구 테라스는 3.1×0.9 크기의 작은 데크, 벤치, 화분으로 제한한다.
  지붕과 앞벽이 없는 기존 직교 시점을 유지한다.
- 아지트 탭에서 후보를 선택한 뒤 적용한다. 시설과 기본 가구 배치를 바꾸되 이름,
  대표 사진, 모임 메모, 색상, 추억을 유지한다. 추억 액자가 새 가구와 겹치면 빈자리로
  옮기고, 모두 수용할 수 없으면 기존 방을 유지하며 이유를 안내한다. 적용은 실행 취소 가능하다.
- 내 자리에서 이름·대표 사진·모임 공지·모임 색상·캐릭터 옷을 바꾼다.
  클라이밍은 홀드/매트 색, 다이닝은 피자/라멘/디저트 소품도 고를 수 있다.
- 전시칸은 비워서 시작한다. 사용자가 추가한 추억 액자에 사진·제목·메모·활동 링크를
  담고 선택해 다시 본다. 대표 사진과 가장 최근 전시한 액자 두 개를 벽 게시판에도 보여준다.
  게시판의 기록을 눌러 같은 편집 패널을 연다. 개인 활동을 자동으로 가져오지 않는다.
- 모임 사진은 JPG/PNG/WebP 5MB 이하를 브라우저에서 최대 640px JPEG로 줄여 저장한다.
  서버 업로드가 아니며 사진당 데이터 길이를 제한한다. 저장 실패 시 편집 내용은 유지한다.
  취소/선택 변경/템플릿 변경/실행 취소 후 늦게 완료된 사진은 반영하지 않는다.
- 저장 형식 v2는 같은 저장 키의 기존 v1 배치와 메모를 읽어 호환한다.
  불러오기만으로 기존 저장 데이터를 덮어쓰지 않는다.
- 사진·제목·메모를 분석 속성에 넣지 않는다. 새 조작도 고정 action 식별자를 쓴다.
- 데스크톱은 우측 편집 패널, 모바일은 높이를 제한한 스크롤 패널이다.
  키보드용 가구 목록/방향 버튼, 44px 조작 영역, 오류/저장 상태 안내를 유지한다.
- 서버 공동 저장·모임 생성 화면 추천·기존 후기 API 연결·실시간 캐릭터 이동은 후속 범위다.
  이번 화면은 기존 브라우저 저장 편집기 안에서 동작하며 실제 모임원 접속을 표현하지 않는다.

## 화면과 동작

- `/space/studio`는 독립된 전체 화면 편집기다. 기존 모임 데이터와 혼동하지 않도록
  체험 공간임을 표시한다. 서버 공간 API가 없으므로 저장 범위는 현재 브라우저다.
- Layout: 상단 68px 탐색/저장, 중앙 Three.js 직교 카메라 공간, 하단 가구 카탈로그.
  중앙은 화면 크기에 맞추고 가구 목록만 가로로 스크롤한다. 작은 화면은 하단
  카테고리와 아이템을 두 줄로 배치한다. 편집 패널만 세로 스크롤한다.
- 독립된 가구 모델을 선택하고 드래그하거나 방향 버튼으로 옮긴다. 90도 회전,
  삭제, 추가, 실행 취소/다시 실행을 제공한다. 바닥 밖/가구 중첩 배치를 막는다.
- 벽/바닥 테마, 공간 이름, 추억 액자 제목/메모를 편집하고 저장/취소한다.
- 기본 인물은 장식 캐릭터이며 접속자/참여자로 표현하지 않는다.
- 시점 전환, 확대/축소, 전체 보기. 모바일 터치와 키보드 대체 조작을 지원한다.

## 구현 경계와 검증

### 장면 변경의 GPU 준비

- 이동·카메라 전환과 정지 화면은 같은 선형 HDR 렌더 타깃을 사용한다. 출력 색공간 차이로 같은 재질의 셰이더를 이동 시작 시 다시 만들지 않는다.
- 층·외관을 숨길 때 해당 가구 조명은 밝기만 0으로 만든다. 렌더러가 받는 조명 개수는 유지하며, 보이는 조명의 색·광량·월드 위치는 원본을 따른다. 가구 추가·삭제 때만 조명 구성을 다시 찾는다.
- 새 장면의 재질을 비동기로 컴파일하고, 숨겨진 층과 외관도 화면 밖에서 준비한 뒤 실제 프레임의 GPU 완료를 확인하고 로딩을 닫는다. 로딩을 닫은 직후 첫 드래그로 준비 비용을 넘기지 않는다. 새 요청·컨텍스트 손실·해제 이후에는 이전 준비 작업을 무시한다.
- 그림자 끄기는 셰이더 구성을 바꾸지 않고 그림자 강도를 0으로 만든다. 꺼진 동안에는 기존 그림자 맵을 재사용하고 다시 켜면 갱신한다.
- 가구 썸네일은 완료한 종류별로 캐시한다. 목록을 닫거나 테마를 바꾸어 생성을 중단해도 다음에는 미완료 항목부터 이어서 만든다. 썸네일 크기와 장면의 해상도·재질·그림자 품질은 이 최적화에서 낮추지 않는다.

Three.js는 기존 의존성을 재사용한다. 배치/저장 순수 함수, 렌더러, React 화면을 분리한다.
배치 유효성/손상된 저장 데이터/저장 실패/취소/다시 실행을 Jest로 검증하고,
실제 브라우저에서 드래그·터치·시점 변경·재접속 저장과 390px/1440px 화면을 확인한다.
별도 QA 에이전트는 사용하지 않는다. 서버 공동 저장/동시 접속은 구현 범위에 포함하지 않는다.
