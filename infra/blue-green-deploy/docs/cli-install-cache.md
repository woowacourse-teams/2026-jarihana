# 운영 배포의 AWS CLI 설치 재사용

`backend-bluegreen-phase.yml`은 plan, switch, observe, seal 등에서 AWS CLI를 준비한다.
기존에는 단계마다 공식 ARM64 압축 파일을 내려받고 설치한 뒤 삭제했다. 2026-11-16 운영
실행 `43859030449`에서 네 단계의 설치 시간은 10초, 6초, 8초, 8초로 합계 32초였다.
이 변경은 해당 준비 비용을 줄이며 파일 전송이나 앱 전환, 관찰, 복구 조건은 바꾸지 않는다.

## 설치와 재사용

GitHub가 제공하는 `RUNNER_TOOL_CACHE` 아래 `jarihana-awscli`에 버전, 아키텍처와 원본
SHA-256을 포함한 경로로 설치한다. 별도의 GitHub 변수나 호스트 전역 PATH 변경은 없다.
고정 버전은 기존과 같은 2.38.5다. 같은 전용 coordinator runner의 후속 단계/실행이 재사용한다.

- 최초 설치는 공식 압축 파일의 기존 고정 SHA-256을 검사한 뒤 기존 AWS 설치기를 실행한다.
- 재사용 전 모든 일반 파일의 SHA-256과 전체 파일 목록, 권한, 심볼릭 링크 대상을 대조한다.
  저장된 해시 목록이 일부 누락되어도 다시 계산한 전체 목록과 일치하지 않으면 재사용하지 않는다.
- 무결성 확인 후 실제 CLI 버전을 확인하고 성공한 경우에만 해당 job의 `GITHUB_PATH`에 추가한다.
- 누락되거나 손상된 설치본은 공식 압축 파일을 다시 검증해 재설치한다. 다운로드/체크섬/설치가
  실패하면 PATH를 등록하지 않고 실패한다. 기존 시스템 CLI로 몰래 전환하지 않는다.
- 동시 설치는 `flock`으로 직렬화하며 잠금 획득 제한은 180초다. 임시 다운로드는 성공/실패 시
  정리하고 설치 도중 실패한 캐시는 제거한다. 강제 종료로 남은 불완전한 캐시는 다음에 재검증한다.

캐시 루트는 배포 계정 소유의 0700 디렉터리여야 하며 루트/잠금 파일의 심볼릭 링크를 거부한다.
이 캐시는 신뢰하는 운영 전용 runner의 로컬 설치본이다. 같은 계정의 악성 프로세스가 파일과
검증 목록을 함께 바꾸는 공격을 방어하는 별도 보안 경계는 아니다. PR runner와 공유하지 않는다.
자격증명은 저장하지 않으며 AWS CLI의 기존 자격증명 해석을 사용한다.

## 운영 서버 비교 결과

2026-11-17에 운영 coordinator(t4g.micro, 메모리 916MiB)의 실제 `jarihana-coordinator`
계정으로 측정했다. 운영과 같은 AWS CLI 2.38.5 원본, 고정 체크섬과 설치기를 사용했다.
한 배포의 CLI 준비 4회를 묶어 각 조건을 3회 측정했다. 기존/최초 생성 조건은 순서를 교차했고
재사용 조건은 이후 실행했다. 호스트 부하나 OS 파일 캐시는 통제하지 않아 편차가 있다.

| 조건 | 4회 준비 합계의 세 측정값 | 중앙값 |
| --- | --- | ---: |
| 기존 매번 설치 | 24.180초, 27.240초, 28.113초 | 27.240초 |
| 캐시 최초 생성 1회와 재사용 3회 | 32.374초, 24.257초, 24.675초 | 24.675초 |
| 이미 설치된 캐시 재사용 4회 | 5.576초, 11.313초, 11.960초 | 11.313초 |

후속 실행의 준비 구간 중앙값은 15.927초, 58.5% 줄었다. 최초 생성까지 포함한 중앙값은
2.565초, 9.4% 줄었지만 첫 측정은 기존보다 느렸다. 최초 설치가 항상 빨라지는 변경이 아니다.
전체 배포가 아니라 설치/무결성 검사/PATH 등록 구간이며 단계 후 S3 읽기 시간은 제외했다.

최종 후보로 37회 실제 S3 pointer 읽기가 성공했고 내용은 유지됐다. 캐시 실행 파일에 손상을
주입한 뒤 재설치, 동시 두 호출의 단일 설치, 임시 파일 정리를 확인했다. 운영 저널과 설정의
해시가 유지됐고 공개 사이트가 HTTP 200으로 응답했다. 시험 디렉터리와 시험 캐시는 전부
삭제했으며 실제 runner 도구 캐시에는 변경을 남기지 않았다.

로컬에서는 기존 계약 333건과 저장소 밖 캐시 경계 검사 21건, Bash/ShellCheck를 통과했다.
추가 검사는 손상/파일 추가/누락/링크 변경, 잘린 해시 목록, 다운로드/체크섬/설치/버전 오류,
설치 취소 후 정리와 재설치, 캐시 권한과 루트/잠금 링크 거부를 확인한다. Alpine 시험 이미지의
BusyBox find는 `-printf`를 지원하지 않아 해당 시험은 운영처럼 GNU 도구를 쓰는 Ubuntu에서 실행했다.
실제 공식 압축 파일은 서버에서 검증했고 로컬 실패 주입은 대역이다. 추가 시험 파일과 원시
측정 로그는 저장소 밖에만 보관한다.

## 검증 범위와 운영 반영

서버 시험은 운영 coordinator의 실제 배포 계정에서 격리된 임시 경로를 사용한다. 공식 CLI의
설치/재사용 시간과 실제 IAM을 통한 S3 pointer 읽기를 확인한다. 정식 GitHub 배포나 실제
앱 전환을 실행한 결과는 아니며 전체 배포 시간의 개선율로 해석하지 않는다.

운영 workflow는 main 실행의 SHA를 checkout한다. 서버에서 시험 파일을 실행한 것만으로 다음
배포에 적용되지는 않으며 코드가 main에 반영되어야 정식 경로에서 사용한다. 새 서버 설정은 필요 없다.
되돌릴 때는 이 코드와 workflow 정리 변경을 함께 되돌리면 기존 매 단계 설치를 사용한다.
재사용 캐시는 실행되지 않는 잔여 파일이 되며 배포가 없는 시점에 해당 버전 디렉터리를 정리한다.
오래된 버전을 자동 삭제하는 정책은 추가하지 않았다.

[AWS CLI 설치](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html).
