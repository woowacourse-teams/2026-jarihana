# 배포 점검 지표 변경의 운영 적용 상태

기록 시각은 2026-10-29 14:21 KST다. 이 문서는 코드 배포와 SSH 선반영을 구분한다.

| 항목 | 상태 | 적용 경로 |
| --- | --- | --- |
| 운영 Nginx 내부 점검 표시, 공개 요청의 표시 제거 | SSH 선반영 완료 | 기존 활성 설정을 백업하고 검사 후 graceful reload |
| PROD 배포 관측 주기 | SSH 선반영 완료 | `jarihana-observability@prod.timer`의 prod 전용 drop-in에서 수집 완료 후 30초 대기 |
| Grafana 수집기/라우팅 관측 만료 | 이 PR 배포 대기 | `develop` 머지 후 모니터링 자동 배포로 45초에서 90초로 변경 |
| HTTP 요청 수/오류율/응답 시간에서 점검 제외 | 별도 백엔드 PR 배포 대기 | `main` 머지 후 운영 백엔드 자동 배포 |
| Nginx 템플릿, 직접 점검 스크립트, 타이머 설치 정의의 영구 코드화 | 후속 작업 | 서버 설정을 저장소/고정 제어 릴리스로 일치시켜야 함 |

Nginx는 내부 `/__deployment` 요청을 `GET /api/groups?size=1`로 전달할 때
`X-Jarihana-Deployment-Probe: true`를 주입한다. 공개 `/api/` 경로는 클라이언트가
보낸 같은 헤더를 제거한다. 백엔드 필터가 배포되기 전에는 점검도 기존 HTTP 지표에 포함된다.

운영에서 확인한 내용은 Nginx 설정 검사 성공, 내부 점검 연속 3회 성공, 공개 API 정상 응답,
타이머의 `OnUnitInactiveUSec=30s`, 수집기 실행 성공과 실제 Nginx 경로 관측 성공이다.
기존 서버 설정의 백업은 Nginx 서버의 root 전용 `/var/backups/jarihana-probe-20261029T052146Z`에 있다.

## 임시 선반영의 한계와 후속 작업

- 보호된 배포 제어 태그와 A/B 호스트의 고정 SHA는 변경하지 않았다.
- 기존 제어 릴리스의 Nginx 템플릿은 다음 트래픽 전환에서 점검 표시를 덮어쓸 수 있다.
  백엔드 PR을 배포한 뒤 활성 Nginx 설정을 다시 확인하고 필요하면 표시를 재적용한다.
- 후보 직접 검사의 스크립트 표시는 아직 운영 제어 릴리스에 포함되지 않았다.
  해당 호출은 계속 HTTP 지표에 포함될 수 있으며, 이 문서는 모든 점검이 영구 제외됐다고 주장하지 않는다.
- 후속 코드화에서는 공개 경로의 헤더 제거, 내부 경로/직접 검사의 표시, 30초 타이머와
  기존 prod drop-in 정리를 함께 관리한다. 새 불변 제어 태그를 만들고 기존 설치 규칙에 따라
  coordinator/A/B의 ref/SHA를 일치시킨다. 기존 태그를 이동하지 않는다.
- Grafana 90초 기준이 배포되기 전에는 기존 45초 기준이 적용된다. 현재 수집은 약 3초에
  완료돼 30초 대기와 합쳐 약 33초 간격이지만, 지연 시 기존 알림이 발생할 수 있다.
- 이 PR은 서버 설치 코드, Nginx 템플릿, 배포 제어 패키지와 타이머 unit을 변경하지 않는다.

현재 운영 배포 관제의 네이티브 V2 정의는 기존 `develop`에 없었으므로, 이 PR에 원본,
쿼리 카탈로그, 생성기와 생성 JSON을 함께 포함한다. Nginx/EC2 상태를 새로 조작하지 않고
기존 운영 수집기가 보내는 지표를 읽는다. 생성 파일은 직접 수정하지 않고
`node infra/monitoring/grafana/deployment/build-dashboard.mjs`로 재생성한다.
